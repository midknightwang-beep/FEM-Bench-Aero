## 一、执行摘要

本项目已完成数据集（FEM-Bench-Aero）的初步构建：形成 **41 条算例 × 2 棵求解器树**（CalculiX 发布树 + Abaqus 交叉验证树）、覆盖 **4 个结构族 7 种结构形式**、按物理维度划分为 **40 个几何等价类**（train 17 / val 13 / test 11），全部数据通过**九道质量闸**验证（网格质量 41/41、双求解器交叉 41/41、语义门禁 82/82、退化自检 50/50、分组回归 9/9 等），并实测取得**双求解器等效模量偏差 0.003%** 的标签可信度背书。

数据集建成的意义，是为整个项目立起了"考卷与标尺"。本计划回答"接下来做什么"：按**五个阶段**推进——

1. **P1 评测基线**：先定"怎么考"——制定评测协议，跑通端到端基线；
2. **P2 算法开发**：再教"怎么生成"——检索增强、约束生成、自修复闭环；
3. **P3 验证评估**：自动评测与专家盲评双重验收；
4. **P4 集成部署**：从脚本到交互式原型系统；
5. **P5 迭代推广**：失败样本回流、数据集放量、真实项目试点，形成数据飞轮。

该路线与当前该领域国际主流工作（ALL-FEM、AbaqusAgent、ModiGen 等）的成熟路径一致，且本项目在数据质量体系（九道闸、双求解器交叉验证）上比多数公开工作更严格。每个阶段均有可验收交付物，便于按里程碑考核。

## 二、现状与起点

### 2.1 已完成的核心资产

**（一）数据集 FEM-Bench-Aero（主要成果）**

- 规模：41 条算例 × 2 棵树（modeling 发布树 / _xval 交叉验证树），跨树模型逐字节同构；
- 覆盖：翼盒（含后掠/锥形平面形状、多闭室）、加筋平板壁板、机身柱壳（含尺寸·壁厚维）、开孔板（含材料维复材层合）——**7 种典型飞机结构形式 T1–T7 全部落地**；
- 划分：train 17 / val 13 / test 11，按"规则化谓词 + 几何等价类"划分，物理维度外推式评测，杜绝随机抽样的信息泄漏；
- 质量：九道闸全绿——网格质量（min Jacobian ≥ 0.30 且零三角）、双求解器交叉（位移差 < 1%、应力中位差 < 5%）、语义门禁（派生预期与几何实测精确相等）、载荷-反力平衡（残差 < 1e-3%）、退化自检 50/50、去重指纹、分组回归 9/9 等。

**（二）生成与求解链路（配套资产）**

- 参数化建模流水线：自然语言契约（FEASpec）→ 参数化建面 → 全四边形网格 → 双后端求解器 deck 自动写卡 → 结果提取与闸验收；
- 独立验证线：解析解对标（Howland 开孔应力集中、CLT 复材等效模量等）+ 双求解器互证，标签可信度有实测背书（双码等效模量偏差 0.003%）。

### 2.2 数据集在项目中的定位

数据集不是附属产物，而是整个技术框架的**标尺与地基**：

| 角色 | 机制 |
|---|---|
| 考卷 | val/test 规则化划分定义评测集，等价类定义能力边界 |
| 教材 | train 集作检索示范库 / 微调语料 |
| 标尺 | 闭式解真值 + 双求解器交叉标签，给每次生成自动打分 |
| 闸门 | 数据集入库闸与生成结果放行闸同一套代码，同源复用 |

## 三、总体路线

### 3.1 五阶段路线

```
P0 数据集初步构建（已完成）
   ↓
P1 评测基线 ──→ P2 算法开发 ──→ P3 验证评估 ──→ P4 集成部署
   ↑                                              │
   └──────────── P5 迭代推广（闭环生长）←──────────┘
```

- **P1 → P2 → P3 严格串行**：没有冻结的考卷，模型改进就无法量化；
- **P4 与 P3 后半可并行**：集成开发不阻塞评估收口；
- **P5 与 P1–P4 构成循环**：每轮迭代回到数据集，越用越强。

### 3.2 与主流成熟做法的对齐

| 主流做法 | 代表工作实测结论 | 本项目对应 |
|---|---|---|
| 评测基准先行 | ALL-FEM 以 39 个基准验收系统（代码级成功 71.8%） | P1 冻结 val/test 考卷与指标 |
| 检索增强（RAG） | AbaqusAgent：RAG 覆盖内成功率 92.5%，覆盖外 60% | P2 以 train 集等价类建检索库 |
| 自修复闭环 | 无 Reviewer 环节成功率 90% → 45% | P2 闸报错→归因→修复闭环 |
| 结构化约束生成 | 领域实践：schema 约束 + 确定性渲染显著降幻觉 | P2 契约（FEASpec）限定生成空间 |
| 领域微调（按需） | ModiGen：SFT+检索+反馈使小模型超过前沿大模型零样本 | P2 消融后视需要轻量微调（LoRA） |
| 专家盲评 + 解析解对标 | 领域通行验收方式 | P3 双重验收 |

**差异化优势**：本项目数据集带九道闸与双求解器交叉标签，"闸即标准"同源复用，生成结果的放行标准与数据集构建标准完全一致——这是多数公开工作不具备的。

## 四、各阶段实施计划

### 4.1 P1 评测基线（先定怎么考）

**目标**：让"生成得好不好"可量化、可复现、可对比。

**主要任务**

1. 制定评测协议：定义指标体系（一次通过率、语法/物理合法率、与真值偏差、交互轮次效率、修复收敛轮数），冻结 val/test 考卷；
2. 搭建端到端基线系统：通用大模型 + 提示词工程直连现有建模流水线（spec → 建面 → 网格 → deck → 求解 → 闸验收）；
3. 首轮全量评测：产出基线成绩单，明确当前能力底座与差距分布。

**交付物**：评测协议文档、基线系统、基线成绩单。
**验收标准**：评测可一键复跑、成绩单数字可溯源到命令与产物路径。
**数据集角色**：val/test 定考卷；train 只做示范，划分规则化防泄漏。

### 4.2 P2 算法开发（教怎么生成）

**目标**：在基线之上显著提升合法率与一次通过率，重点是"物理正确"而非"看起来对"。

**主要任务**

1. 检索增强（RAG）：以 train 集等价类为检索库，为生成提供结构相似的 few-shot 示范；
2. 约束生成：以契约 schema 限定输出空间（参数类型、枚举、取值范围、依赖关系），从源头压制幻觉；
3. 自修复闭环：闸报错 → 自动归因（语法/网格/物理分类）→ 迭代修复，形成"生成—验收—修复"循环；
4. 消融实验：逐项量化各机制贡献（检索/约束/修复），据此决定是否引入领域微调（优先轻量 LoRA 路线）。

**交付物**：生成算法模块（含检索库、约束层、修复循环）、消融对比报告。
**验收标准**：每轮迭代在冻结考卷上成绩可量化提升；消融结论有数据支撑。
**数据集角色**：train 集做检索库与（可选）微调语料；等价类定义"会什么"。

### 4.3 P3 验证评估（双重验收）

**目标**：证明可信——不止自说自话，用自动标尺与领域专家双重背书。

**主要任务**

1. 全量自动评测：val/test 全量跑生成→求解→闸验收流水线，对标闭式解真值与双求解器交叉标签；
2. 专家盲评：邀请结构强度工程师对生成模型与人工模型做盲评对比（可建模性、可复用性、结果可信度）；
3. 效率对比：同一典型任务的人工建模耗时 vs 系统生成耗时（对照行业公开数据：同类系统单模型 6–25 分钟 vs 人工 25 分钟级）。

**交付物**：评测报告、专家意见记录、典型案例集（含失败案例归因）。
**验收标准**：自动指标达标 + 专家盲评认可；失败案例全部有归因与改进项。
**数据集角色**：真值标签自动打分（背书：双码偏差 0.003%）；九道闸做放行闸。

### 4.4 P4 集成部署（落地）

**目标**：从脚本原型到可演示、可使用的交互式系统。

**主要任务**

1. 流水线服务化：建模—求解—验收链路封装为服务，支持排队与并发控制（求解器许可约束）；
2. 交互界面原型：自然语言输入 → 澄清追问 → 模型生成 → 结果可视化（应力/位移云图、关键读数）→ 报告导出；
3. 工程工具链对接：与现有强度分析流程（含 Abaqus 工作流）打通，输出可直接复用的模型与读数。

**交付物**：原型系统 V1、现场演示、接口文档。
**验收标准**：现场演示端到端跑通典型任务；生成结果通过同一套九道闸。
**数据集角色**：生成结果直接进数据集同款闸门验收，标准不漂移。

### 4.5 P5 迭代推广（闭环生长）

**目标**：系统越用越强、覆盖越来越广，形成数据飞轮。

**主要任务**

1. 失败样本回流：评测与试用中的失败案例经专家确认后回流数据集（难题挖掘），下一轮训练/检索即覆盖；
2. 数据集放量：按物理维度扩展——铺层族与厚度维（复材）、更多结构形式，每次放量先声明划分再入库；
3. 真实项目试点：选取 1–2 个真实型号预研任务做受控试点，量化效率与质量收益，修订后推广。

**交付物**：系统 V2、放量后数据集、试点总结报告。
**验收标准**：试点任务效率收益可量化；数据集规模与等价类覆盖增长可查。
**数据集角色**：数据集随应用持续生长——这是"标尺"长期保持有效的关键。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 大模型生成"看着对、物理错" | 错误模型流入工程环节 | 不依赖模型自觉，九道闸硬性拦截；闸已实测能咬住指纹撞车、公式错误等真问题 |
| 覆盖面不足（7 种形式之外不会做） | 试用受挫、预期落差 | P5 失败回流 + 按物理维度放量；对外明确声明能力边界（数据集 manifest 已记账） |
| 评测泄漏（考题混入训练） | 评测虚高、误导决策 | 划分规则化 + 等价类互验断言；val/test 冻结，考卷不参与任何训练/检索 |
| 微调成本高、周期长 | 拖累进度 | RAG + 约束 + 自修复先行（主流实证已够用），微调仅在消融证明必要时上轻量路线 |
| 求解器许可与算力约束 | 评测与试跑排队 | 并发排队与算例规模分级；开源求解器（CalculiX）承载批量评测，商业求解器承载抽检 |

## 七、保障机制

1. **闸即标准**：数据集九道闸与生成结果放行闸同一套代码，标准同源、永不漂移；任何判据改动必须留档重签（D 系列决议 29 条全部可溯源）。
2. **防泄漏纪律**：划分规则化 + 等价类黑名单互验，已入库断言；评测考卷冻结。
3. **可复现纪律**：每个结论绑定"命令 + 实测数字 + 产物路径"，评审可逐条复核。
4. **能力边界声明**：数据集 manifest 显式记账未覆盖维度（如层间/逐层应力、接触、非线性外形），不做过头承诺。

## 八、结语

数据集初步构建完成，标志着项目从"打地基"进入"起楼房"阶段。本计划以"先定怎么考、再教怎么生成、双重验收、闭环生长"为主线，五个阶段环环相扣、每个阶段可验收，且与国际主流成熟路径对齐、在数据质量体系上更严。恳请领导审阅，如获批准，将按 P1 评测基线启动实施。
