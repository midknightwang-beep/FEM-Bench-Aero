## 4. 核心设计：豁免只能精确到原因

**最容易写错的写法是「按 sid 豁免」** —— 那样只要加了 `--public`，协议文件真的写死计数、`PY=` 真的写成裸 `python`，也一并放过，等于把配据废掉。所以每条豁免都配一个**谓词**，回答的是「失败原因是不是恰好公开集造成的」：

| id | 豁免条件（谓词） | 什么情况下**仍判红** |
|---|---|---|
| `C-013` | artifact 是**渲染层占位符**（`{{DATA_ARCHIVE}}/...`） | artifact 是普通相对路径却不存在 |
| `S-46` | `PY=` 的值含 `{{`/`}}` | INDEX 无 `PY=`、或 `PY=` 是裸 `python` |
| `S-51` | `AGENTS.md` 与 `CLAUDE.md` **都不存在** | 任一存在（内容是否违规另说，**对象存在就不给豁免**） |
| `S-56` | 同上 | 同上 |
| `S-61` | 红点集合**恰为 `{H1}`**（hook 缺失） | 红点含 H2/H3（有 hook 但内容/指向不对） |

R69 三条边界落在代码里：① 不带参数时 `public_mode=False`，整条分支不进；② 谓词决定；③ `ok=True` + `skip=True` + `exempt=True` + `reason`，四者同时成立才算豁免，且 `skip` 使它**不计入通过数**。

## 6. 两个坑（都是「主仓全绿」掩盖的）

### ① `public_mode` 未定义 —— 主仓全绿，快照才炸

首版结构层写了 `if problems and public_mode and ...`，但 `main` 里只有 `args.public`，没有 `public_mode`。

**主仓完全看不出来**：所有 artifact 都存在 ⇒ `problems` 为空 ⇒ `and` 短路 ⇒ 那段代码压根没执行。到快照里（C-013 的 artifact 确实不存在）才 `NameError`。

同族于 N-26 / NC-47：**判据没跑起来，与判据通过外观一样**。修法是把开关提成具名局部变量，并在注释里写明「为什么不能靠主仓验证这条路径」。

### ② `PATH_RE` 的字符类不含 `{}` ⇒ 占位符被截成半截路径

`{{DATA_ARCHIVE}}/SHA256SUMS.txt` 被 `PATH_RE` 匹配成 **`/SHA256SUMS.txt`** —— 看着像「仓库根目录下的文件」，实际是外部归档。这会让豁免谓词永远不成立，也会让任何读 `artifact` 字段的人得出错误结论。

**这是信息失真，不只是豁免判断问题。** 同族于 T-D4 那次 `\.(?:json|jsonl)` 交替写反把 `x.jsonl` 截成 `x.json`：**正则没覆盖输入的实际字符**。修的是字符类（补 `{}`），不是豁免条件 —— 补完后主仓 P1 仍逐字节一致（主仓没有占位符形态）。

## 7. 已知问题 / 未验证

1. **`--public` 之后仍然红的 2 项（S-39 / S-43）没有豁免**，因为它们**可以自愈**（`npm install`）。这也是 `--public` 不该被当成「让自检变绿」的开关的实证 —— 加了还有红，说明红是真问题。**F-1 仍挂账**：`npm install` 现在只在「已知问题」表里，步骤区没有。
2. **`--public` 不改变公开集内容**。F-2（`package-lock.json` 被 `.gitignore` 忽略 ⇒ 进不了新库）与 D3（行尾）都未动。
3. **C-013 的豁免是临时性的**：D2 发布数据包、把 artifact 换成下载地址后，这条豁免应当撤销（`_PUBLIC_EXEMPT_REASON` 里已写明）。届时若无人工销，它会**静默保留** —— 这是本设计的一个已知风险，缓解手段是 R75 要求「豁免清单必须能被读懂」，但它没有闸守。可考虑后续加「豁免数量变化必须有人审」的判据。
4. **未加负控**（NC-68 之类）。代价：只跑 `negative_controls.py` 的人看不到这六向的结果。理由与 T-D5 相同 —— 加 NC 会牵动 C-019 → INDEX → S-44 / NC-49 那条循环依赖。改用独立自检脚本，并写进 AGENTS §0。
