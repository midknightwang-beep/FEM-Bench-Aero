## 1. 一句话

## 2. 为什么先做影子批，而不是直接改 `SYS`

`check_claims.py:2394-2406` 的 **S-39** 要求 C-032/C-033 成绩单的 `provenance.prompt_sha256` == 生成器当前 `SYS` 的 sha256。
**一旦改 `SYS` 常量，四份 prompt-v2 代成绩单立刻与源码不等、S-39 必红**，此时不重跑就提交不上；要重跑就得全量重生成 64 条 × 2 模型 + 重打分（含求解）。

所以分两阶段（契约 §4）：

- **阶段 1（本轮）**：给生成器加 `--sys-file`，`SYS` **常量一个字节不动**（sha 实测仍是 `ce225186…`），跑影子批量化收益；
- **阶段 2（待拍板）**：正式改 `SYS` + 全量重跑 + 更新成绩单。

`--sys-file` 的三条自保（均已实测）：
1. 不传参时行为与旧版逐字节一致 —— `--print-prompt-sha` 仍输出 `ce225186cafa5d55…`（前值）；
2. 不能用于 L2 —— 会把 L2 追加段丢掉，实测 `RC=2` 且在调用模型前退出；
3. 影子 prompt 的 sha 单独记进候选的 `prompt_sha256`，事后可分辨哪批是影子。

## 3. 影子 prompt 怎么产生（确定性，不手抄）

`_psa_build_prompt.py` 从 `gen_candidates_v2.js` **逐字节提取** `SYS`，再施加定点替换：

| `b` | C1 顶层 7 块 required 显式化 + C2 `material` 五键 + C3 网格键去 `size` | `73e779808d67cdad…` |
| `bplus` | `b` + C4（各块允许键白名单前置） | `d9c0b02d04119089…` |

## 6. 报告 §11 的假设被推翻：「省一轮」不属于方案 B

`task_b1kpi_report.md` §11 写「收益是可量化的省一轮」。实测：**B 清零了 21 条目标错误，但没有一条题因此首轮通过**——因为每道题**同时**还夹着 1–3 个自创键（`analysis.type` 最常见）。

⇒ 只要还有任何一个自创键，闸就不放行，轮数不变。**「省一轮」是一个「全有或全无」的效应，不是「修一部分省一部分」。**

B+ 之所以有效，是因为它把 `gen_candidates_v2.js:220-227` 里**早就存在的 `ALLOWED_HINT`**（原本只在修复轮把错误推回时才给模型）前置到了首轮。

> **机制一句话**：模型首轮写自创键 → 闸拒 → 修复轮里收到「允许键: …」→ 改对。
> 于是 **L1 修复成功率 100% 的本质 = 这份清单在第二轮才出现**。把它挪到第一轮，那 100% 就变成「本来就不需要修复」。

这也给 T-B1KPI 的「L1=100% 是闸严格度的影子」补了机制层的解释。

### 10.1 p3 的塌陷（本轮最大的坑，值得单独记）

p3 把首轮结构通过率从 0/59 拉到 39/59，**看上去是巨大成功**；同一批成绩单的 TSR 却是 **92.0% → 36.0%**。

根因不是模型变笨，是**我让 prompt 教了 gold 里不存在的键**：C4 的「允许键白名单」抄的是 ajv 错误原文，而那条原文是

```
/mesh 不允许的键 "size"，请删除。mesh 允许键: size_chord/size_span/order/refine_le
```

`order`/`refine_le` 是 **schema 合法、但 64 条 gold 一条都没有**的键（gold 用的是 `element_order`/`refine_at_leading_edge`）。模型照单全收，38/59 条写了它们，`spec_fidelity` 判「自创键」⇒ FAIL。

⇒ **「结构闸通过」和「答案对」是两个判据**，只报前者会把一次 56 个百分点的塌陷读成成功。这条已写进契约 Q8。

- **glm 六格全是 92.0%**：prompt 三代对它零影响。

## 11. 结论

### 11.1 这个改动到底值多少（按 N-31 的口径读）

**可归因的收益（远超噪声）**：

| 指标 | 基线（128 条候选） | 改后 | 量级 |
|---|---|---|---|
| `material` 缺 required | 174 条 | **0** | 三个数量级 |
| `mesh` 缺 required | 42 条 | **0** | — |
| `size` 被拒 | 21 条 | **0** | — |
| 首轮有效题数 | glm 5 / ds 3 | **28~48** | 10 倍 |

**不可归因的部分（噪声带内）**：exam TSR 的 ±1~2 条、`fabricated` 的 0↔1↔2。

⇒ **结论：这次对齐买到的是「效率」，不是「准确率」。** 准确率本来就主要由模型决定，prompt 只决定「第一轮能不能写对格式」。这也顺带把 T-B1KPI 那个「L1 修复成功率 100%」解释清楚了：**修复轮给的清单在第二轮才出现，所以第一轮必然错、第二轮必然对**——那 100% 是清单出现时机造成的，不是模型会改错。

### 11.2 三个必须记住的教训

1. **只算一个口径会漏掉最严重的回归**（§10.1）。结构闸全绿而 TSR 塌 56pp，只有并报才看得见。
2. **修复轮的提示语本身就是错误来源**。`ALLOWED_HINT` 抄的是 schema 生成的话，于是「把提示前置」= 「把 schema 的错误提前」。
3. **`temperature: 0` 不等于可复现**（N-31）。同题同 prompt 连跑两次，一次 `spec(n_frames=0)`、一次 `clarify(n_frames)`。单次冒烟不能当判据。

## 12. 收口（2026-11-01）：闸红了两轮，两次都不是被测对象的问题

本轮收口不是「把已完成的改动提交」，而是**被闸拦了两次、两次都证明闸自己错了**。记下来是因为它们属于同一类：**判据的代理假设失效**。

### 12.1 F-5 兑现：`latest_scorecard()` 按 mtime 取「最新」

写完全部 8 份实验成绩单后跑负控，`NC-36` 当场红（`msrFalse`）。原因不是成绩单坏了：`latest_scorecard()` 用 `max(mtime)` 挑「最新那份」，而新写的实验成绩单**没有 MSR 段**（没跑求解器），于是「最新」= 「缺 MSR 的那份」⇒ 依赖 MSR 的语义项全部翻红。这是 **F-5** 第一次真的咬人，也说明「按文件时间排序」在**一个目录会同时存在正式产物与实验产物**时必然出错。

**改法**：从 `CLAIMS` 的 C-032 artifact 列取路径（确定性锚点），mtime 只作兜底；加 **NC-70** 断言 `latest_scorecard()` 的返回值 == CLAIMS C-032 引用（当前磁盘确有更新的实验成绩单 ⇒ 改回 mtime 立刻红）。负控 69→**70/70**。

**代价（已量化）**：改了 `latest_scorecard()` 就必须重跑负控 → claims → INDEX 这条链，而这条链再回来又影响 S-44/NC-49（见 12.2）。这轮「加一条负控」的实际成本接近「改一处判据」。

### 12.2 N-33：S-44(b) 的代理假设破了，修的时候又踩了同一个坑

新增 NC-70 后 `check_claims` 报 `S-44` 红，报的是「INDEX 主区间上界 NC-67 ≠ artifact 最大 NC-70 ⇒ INDEX 漏报最新一条」。**INDEX 是对的**（已写 `NC-23..67 + NC-70`）。

查下去发现 70 条负控的真实构成是 `PC-1 + NC-1..67 + NC-15b + NC-70` —— **NC-68/NC-69 从来不存在**。旧判据拿「区间上界」当「最新一条」的代理，隐含要求编号连续，一遇到跳号就误报。顺带纠正一句长期误读：旧文里「69/69」的 **69 是条数**，不是「NC-69 这条负控」。

改成「逐条覆盖」后，**第一版实现是错的**：我从整行提取 `NC-\d+` 当「点名」，而 INDEX 第 26 行在括号里逐条描述每条负控（`**NC-49 四向**`…`**NC-67 五向**`）⇒ 每条编号在正文里都被提到 ⇒ **覆盖恒成立**。

**这个错是负控抓出来的，不是看代码看出来的**：改完跑全量负控，`NC-49` 的 N-2 向（上界 67→66）从「红」退化成「**漏判**」—— NC-67 靠正文那句「**NC-67 五向**」仍判已覆盖。而当时 `check_claims` 是**全绿**的。⇒ 只看主闸，这个退化不会暴露。

**修正**（详见 CONFLICT N-33 与 RUBRIC v6.11）：覆盖只从 `C-0xx：` 之后、第一个 `（` 之前的**清单段**读；找不到清单段判红（不许回退整行扫）；反向加「区间不得虚报」（区间声称的编号必须真在 artifact 里，防把 `NC-23..67 + NC-70` 写成 `NC-23..70` 抹平跳号这种编数）。

### 12.4 这两次红共同的判断法

> **这个判据的「代理」和「对象」之间，是不是靠一个没写下来的假设连着？**

- 12.1：代理 = 文件 mtime，对象 = 「当前该用的那份成绩单」。假设 = 「最新写的就是该用的」。假设在**同目录混放实验产物**时破。
- 12.2：代理 = 区间上界，对象 = 「最新加的那条负控」。假设 = 「编号连续」。假设在**编号跳号**时破。
- 12.2 的第二层：代理 = 行内任何 `NC-x` 字面，对象 = 「清单里声明存在的编号」。假设 = 「提到就等于声明」。假设在**正文逐条列举**时破。

三次都是同一句话：**代理比对象好算，于是被当成对象**。而失效时判据不会「变模糊」，它会**理直气壮地报错**。

### 13.2 一次并行事故：假 FAIL 与一份被污染的成绩单

第一次把四批丢进**同一个后台任务**时，满屏：

```
[FAIL] L3_open_hole_panel_400x200_d40: gates={'pipeline': False} class=env
MSR = 0/4
```

而同一条题**单独跑是 `[ok]`**。根因：先前一次前台跑被 SIGTERM 杀掉，**子进程没死透**（`.solve.lock` 里记录的 `start` 是 15:40:52，而第二个任务 15:42 才启动）⇒ 两个 `msr_l3` 抢同一把 `.solve.lock` ⇒ 求解全部失败，且被判成 `class=env`。

**处置**：kill → 逐字节核对成绩单与备份（33 800 → 213 362 字节，已被写坏）→ 回滚 → 删锁 → 改**单批串行** → 先 `--only` 单条验证（`[ok]`，`1/1 = 100%`）→ 再跑全批。

**教训（这条是我自己违反纪律）**：R61 写的是「不许并行 ccx」，我以为是「不主动并行」，实际要防的是**「以为杀掉了其实没杀掉」**。SIGTERM 杀父进程不等于杀子进程；判断「现在有没有在跑」必须查**产物/锁**，不能查「我刚发过 stop」。

### 13.5 四批全表：pct 上升是「分母变小」造成的，不是变强

| 卷 / 模型 | p2 MSR（分母） | p2 exam | p5c MSR（分母） | p5c exam | exam 通过数 |
|---|---|---|---|---|---|
| v6c × glm | 41/51 (80.4%) | 20/22 | 43/51 (84.3%) | 20/22 | **20 → 20（平）** |
| v6c × ds | 42/50 (84.0%) | 20/21 | 41/48 (85.4%) | 20/22 | **20 → 20（平）** |

| v7 × ds | 48/58 (82.8%) | 19/21 | 42/48 (87.5%) | 18/20 | **19 → 18（−1）** |

**四条 pct 全部上升，但四个分母全部变小。** 其中 v7 侧的收缩很大：glm 59→53、ds 58→48（−10）。⇒ **pct 的上升不能读成「变强」**（R54：分母不等禁止相减、禁止排名）。

分母为什么变小？因为 p5c 改的就是「题面没给数 ⇒ 澄清，别编」。澄清题与无 spec 题不进 MSR 分母 ⇒ **分母收缩正是 prompt 生效的直接后果**，不是坏事，但它同时意味着：

- **v7 上 exam 通过数各掉 1 条**（20→19、19→18）：有些题原本硬算出正确结果，现在改成先问清楚 ⇒ 在「必须给答案」的 exam 判据下记为未通过。**这是「用澄清换不编造」的价格**，与 R20（不得静默编造）方向一致，但对外读数上是负的。
- **v6c 上 exam 通过数持平**（20→20、20→20）⇒ 对外 headline 口径**零变化**。

### 13.6 最终结论

| 判断 | 依据 |
|---|---|
| 换代对 headline 有收益吗 | **没有**。C-032 的 exam 20/22 → 20/22，一个数不变 |
| 对 v7（supporting）呢 | **略负**：两模型 exam 各 −1 |
| 全卷 MSR pct 上升可信吗 | **不可直接引用**：四个分母全变小（R54），pct 上升是换分母 |
| 那 p5c 到底带来了什么 | 只在效率轴：结构首轮错误 174/42/21 → 0/0/0、首轮有效题 3~5 → 28~57；以及「模型更愿意澄清而非编数」这个方向性变化 |

⇒ **不换代**：`SYS` 留在 `ce225186`，C-032/C-033/C-040 不动，p5c 的四份成绩单（已补 MSR 段）作为**完整实验证据**入库。这与 13.4 的初步判断一致，且现在有四批数据支撑，不再是一条批次的推论。

**如果将来要重新评估**，需要的东西很明确：① `--repeat N`（N≥3）把 ±1 条压到噪声以下；② 把「澄清率」作为并列指标（分母收缩本身就是信号，不该只报 pct）；③ 先修 N-29/N-30 的 schema 缺陷，否则澄清路径上还叠着「结构性不可解」的题。
