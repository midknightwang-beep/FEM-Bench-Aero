# T-L27：L2 澄清判据的退化解与加固（L2-7）

- **任务 id**：T-L27（ROADMAP §13 第 4 项「L2-7 退化解加固」）
- **单变量**：澄清判据是否、以及如何对「不看题面的固定字符串」免疫
- **日期**：2026-11-01
- **状态**：判据已实现并双向验证；**接入判分待拍板**（三个选项见 §7）

---

## 1. 结论先行

**一个完全不看题面的固定字符串，能在 L2 全卷拿 100%。** 这不是估计，是 `score_l2.py`
跑出来的：把跨题已知的 **13 个键名**写成一句话，64 题全部 `clarify_ok`。

根因不是某一条元数据缺失，是**三条叠加**：

| # | 事实 | 证据（`tasks/tasks.jsonl` L2 行） |
|---|---|---|
| ① | L2 的 64 条**全部**只缺 1 个字段 | `expected_clarifications` 长度分布 = `Counter({1: 64})` |
| ② | L2 的 64 条**全部**没有 `clarify_aliases` | 计数字段数 = 0 ⇒ 判分只认 ASCII 键名，不认语义短语 |
| ③ | L2 的 64 条**全部**没有 `clarify_wrong_keys` | 计数字段数 = 0 ⇒ `hit_wrong` 恒空，「多问」零代价 |

⇒ `judge_clarify_field_level` 在 L2 上实际退化为：
**「13 个键名里出现该题那一个」⇒ 把 13 个全列一遍 = 全卷通过。**

> 这与 P-1（`overclarify_p1.md`）不矛盾：P-1 论证的是「**多问一句**不该判 FAIL」
> （实测 4/4 假阳性，模型在解释「题面给了 X 却没给 Y」）。本报告指出的是另一个极端：
> **放弃针对性的穷举**。两者需要不同的判据，不能互相替代。

---

## 2. 攻击实测（`score_l2.py --cand <退化解目录>`）

四份退化候选都是**机器生成、完全不读题面**，每份 64 个文件（同一模板套到每道题上）：

| 变量 | 构造 | `clarify_all` |
|---|---|---|
| **A 全局穷举** | 一句「请提供以下参数：hole_d、length、…、width，缺一不可。」 | **64/64 = 100.0%** |
| **B 按族穷举** | 只列该题所属族的全部键名（族池 7 / 4 / 4 / 3） | **64/64 = 100.0%** |
| C 纯列举 k=1 | 该族键名取 1 个，**不带任何谓语** | 14/64 = 21.9% |
| D 纯列举 k=2 | 该族键名取 2 个，**不带任何谓语** | 25/64 = 39.1% |

**B 比 A 更要紧**：它说明「加大全局池」没有用 —— 攻击者只需知道**族**，
而最小族池只有 **3**（`stiffened_panel`）。任何以「列了多少个键」为阈值的判据，
其阈值必须 ≤ 3，否则按族穷举直接穿过。

## 3. 加固判据：`|K| >= 3`（kmax）

`K` = 文本中按 token 边界命中的**池内键全集**（"提及"）；
`Q` = 只出现在索要谓语之后的键（"索要"，实现见 `score_baseline.clarify_mention_split`）。

**判退化 ⇔ `len(K) >= 3`。** 阈值不是拍脑袋：

- 真实候选（v7 的 L2 128 条 + L3 10 条）中，**当前 PASS 的条目 `|K|` 上界 = 2**
  （L2 glm 通过 49：`|K|` 分布 `{1:46, 2:3}`；L2 ds 通过 36：`{1:35, 2:1}`；
  L3 glm 5 条全 1；L3 ds 4 条 `{1:3, 2:1}`）；
- 最小族池 = **3** ⇒ 要列满整族至少 3 个键；
- ⇒ **3 = 实测上界 + 1，且恰好等于「列满最小族」的下界**。两侧都有含义。

### 为什么**不**把 `Q ⊄ expected` 也做成硬判据

实测它会把 **1 条合理回答**判红：`L3_naca4412_wingbox`（ds）问了两个字段
（`n_ribs` 与 `n_stringers_per_skin`），而 expected 只有 `n_ribs`。
它确实"多问"，但不是穷举 —— 而且它对 39% 的残余攻击**没有帮助**（见 §5），
因为攻击者只要不写谓语就能绕开 `Q`。⇒ **只上 `|K|`，不上 `Q` 判据**（`Q` 仍算，只作证据）。

## 4. 双向验证（闸必须两边都能红）

| 方向 | 输入 | 结果 |
|---|---|---|
| **不误伤** | 真实候选 138 条（L2 128 + L3 10） | 判退化 1 条，**翻红 0 条**；通过率一字不变（glm L2 96.1%、ds L2 81.8%、L3 两模型 100%） |
| **能挡住** | 攻击 A（全局穷举） | 100% → **0.0%**（翻红 64 条） |
| **能挡住** | 攻击 B（按族穷举） | 100% → **0.0%**（翻红 64 条） |
| **判分未受影响** | 重跑 `score_l2.py` 对 glm/ds，与 `reports/l2_scores_v7_*.json` 逐字段比对 | 唯一差异是 `label`（由输出文件名生成），其余**完全一致** |

自检 **6/6**（`_l27_degenerate_scan.py --self-test`）：
① 真实单键提问不红 ② 真实「上下文+索要」不红 ③ 全局穷举必红
④ 按族穷举必红 ⑤ `|K| = kmax-1` **不红**（钉住阈值，防有人悄悄改成 2）
⑥ `|K| = kmax` 必红。

> ⑤ 这条是给未来的人留的：把 kmax 从 3 改成 2 会让 5 条真实 PASS 翻红，
> 而那属于**改成绩**，不是"加固"。自检必须让它当场红。

## 5. 已知残余（必须随数字一起报）

加固后最优攻击变成「**纯列举 2 个键名、不带谓语**」，实测 **39.1%**（25/64）。
一般的算术是：列 `k` 个键名 ⇒ 通过率 ≈ `k / 族池`，所以

- `k=1` ⇒ 21.9%（实测 14/64）
- `k=2` ⇒ 39.1%（实测 25/64）
- `k=3` ⇒ 已被 kmax 拦住

**为什么不能把 kmax 降到 2**：真实 PASS 里 `|K| = 2` 有 5 条，且都是"指出题面矛盾"这种
有价值的澄清（例：`n_stringers_per_skin=0` 却给了 `stringer_height` 等长桁细节键）。
降到 2 等于**惩罚好行为换 0.6 个百分点**，不划算。

**这个残余在「只改判据」的前提下消不掉**：判据看的是文本形态，而"列 2 个键名"
在文本上与"真实模型简洁地回答了一个字段"无法区分。**根治只能靠题型** ——
给 L2 加入「信息完备、不该澄清」的题（expected 为空），穷举策略会在那些题上全错。
那属于改卷（R65：新版本 + 重冻结 + bridge），不在本报告范围。

## 8. 未验证 / 诚实边界

- 只统计**纯 ASCII 键名**。中文措辞的多问（「还想确认一下肋壁厚」）不计 ⇒ `|K|` 是**下界**，
  判据对中文穷举无能为力（R69 边界：中文没有 token 边界，加边界会把"命中"判成"不命中"）。
- `kmax` 是「数量代理」，不是「意图判定」。一个**真的**指出 3 处矛盾的合理回答会被误判。
  真实 138 条里 0 例，但这是**样本内**结论，不是普遍保证。
- L2 候选只有 v7 的 glm/ds 两份（128 条）；v6c 的 L2 候选不在仓库里，
  所以「不误伤」只在 v7 上验过。
- 攻击 B 的族池按**纯 ASCII** 统计（`wingbox` 7 / `open_hole_panel` 4 / `fuselage_barrel` 4 /
  `stiffened_panel` 3），与 P-1 的 `known_keys` 口径一致。
