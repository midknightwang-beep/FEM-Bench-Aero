## 3. 闸的设计：为什么不是「项数 == 行数」一条

§13 立项时写的最低成本版是「看板里声明的项数 == §4 表里实际行数」。**它只能抓第 1 类（且只抓一半）**：第 2 类是「同一个量的两处声明」，第 3 类是「段内两个数自相矛盾」。

于是做成六条（`roadmap_selfcheck.py`）：

| 判据 | 内容 | 抓什么 |
|---|---|---|
| **R0** | 文件在、四段与合计行都能解析 | 解析不到就红（**不 skip**） |
| **R1** | 四段权重之和 == 100% | 权重被改动后忘改别处 |
| **R2** | 合计 == Σ(权重 × 完成度)；合计格里的 `a×b+…=S` 复算值也须等于合计 | 第 2 类的分母侧 |
| **R3** | 三口径里分母为 `A` / `A+B+C+D` 的行须等于对应数；**其余行必须显式标「无算式」** | 第 2 类（同一个量的两处声明） |
| **R4** | 每段声明项数 == 明细表行数（扣「含 Dxx」显式合并的行） | 第 1 类（含 v2.6「漏计 D2 自己」那种事故） |
| **R5** | 每段算式复算 == 显示完成度；**缺算式判红** | 第 1 类的另一半（85% vs 88%）与第 3 类 |
| **R6** | 段 B「成绩单 X%」== 它的「达标 a/b」 | 第 3 类 |

**R4 的「含 Dxx」不是给我开的后门**：§6 明细表实有 **7** 行（D5 与 D5b 各一行），而 §1 的 D 段说明把 D5b **显式并入** D5（原文就写着「D5 提交闸（含 D5b）」），并按 v2.2 判断「不另计分」⇒ 计分分母 **6**。闸按「行数 − 显式合并数」核，合并必须在说明里写出来；写成「含 D99」而明细表里没有这一行，R4 直接判红。

**两条边界（R69）**

1. **解析不到即判红，不 skip**。这是负控五条 ③。否则「改个措辞」就能让闸失效 —— 而改措辞比改数字容易得多。
2. **无法复算的行必须显式写「无算式」，并由闸在输出里单列点名**（当前是「A+D」那一行：它的分母不是四段加权）。
   豁免要写出来，不许靠「解析不到就跳过」静默放行。

## 7. 边界与未覆盖（不藏）

1. **闸只判算术与分母，不判「完成度估得对不对」**。看板自称「估算，非 artifact」，闸能保证的只是「写了算式、算式能复算、同一个量两处声明相等」。
2. **三口径的「A+D ~71%」没有可复核基数**：它的分母不是四段加权（加权算是 92.1%），定义是「算到 30 天关键判据」。这一行现在**显式标「无算式」并由闸单列点名**，但**它本身仍是一个人类估值**。
   **要不要给它定一个可复算定义，是需要拍板的口径问题**（建议：定义成「A9 是否达成 + D 段是否达成」两项的均值，或干脆删掉这一行；两条都要动对外汇报口径，我不自己拍）。
3. **R5 只认三种算式形态**（`N 项里 X` / `a×b+…=S` / `x/y=p%`）。换一种写法会让闸判红「缺算式」—— 这是刻意的（fail-closed），但意味着**改文档版式时要同步看一眼闸**。
4. **本闸守不到「该写的没写」**：它不能让一段新的进度描述出现，只能保证写出来的数自洽。

## 8. 这一轮我自己犯的两个错（都当场被自检抓住）

1. **R5 首版只复算 `a/b`，没有核右边写的那个百分比**。自检 T7 把 `8.0/9 = 88.9%` 改成 `94.9%` —— 闸**全绿**。
   修成「两边都核」才红。★ 这与 MEMORY 里 T-B2B5 的教训同族：**核了左边忘右边 = 核了一半**。
2. **自检首跑用 `... | tail; echo rc=$?` 取退出码**，拿到的是 `tail` 的 0（`$?` 被管道吃掉，MEMORY「通用坑 B」**第二次犯**）。
   输出里明明写着 `BAD=1`，`rc` 却是 0 —— 重定向到文件才看见真值。**判断闸绿不绿，只能读它自己的结论行，不能读管道退出码。**
