## 4. 豁免清单（固定 5 项，每项带 reason）

| id | 豁免原因 | 边界：什么情况下**仍判红** |
|---|---|---|
| `C-013` | 该 claim 的 artifact 是**本机外部归档**里的 `SHA256SUMS.txt`，公开集按拍板不含它；D2 生效后应由下载地址替代 | 除 C-013 外的**任何** artifact 缺失 / 未追踪 / 落在 `eval_runs` 下 |
| `S-46` | INDEX 的 `PY=` 在渲染层被替换为占位符（本机路径不外泄），判据认不出 venv 特征 | INDEX 里**没有** `PY=`、或 `PY=` 是裸 `python`、或调用行不是 `$PY` |
| `S-51` | `AGENTS.md` 按 D4 拍板①移出公开集 ⇒ 判据对象不存在 | 文件**存在**且内容真的写死了计数 |
| `S-56` | 同上（`AGENTS.md` / `CLAUDE.md` 双双移出） | 任一协议文件**存在**且写死版本/范围/卷名/裸 `python` |
| `S-61` | 公开快照不分发 `.git/hooks`（hook 是本地安装物，不在版本控制内） | 该克隆**有** hook 但内容/指向不对（H2/H3 红不豁免） |

> S-61 等价于已有的 `--skip-hook-guard`，`--public` 内部复用同一条通道，不另造第二套。

## 5. 停止条件（任一成立即停，不自行取舍）

1. P1 不成立（不加 `--public` 时输出有任何差异）
2. 主仓加 `--public` 触发了任何豁免（说明豁免条件写宽了）
3. 公开快照里出现"本该红的没红"（P4/P5/P6/P7 任一失败）
4. 既有闸（负控 / claims / 快照校验 / 提交闸）出现与本次改动无关的红

## 6. R69 三条边界（写进代码注释与 RUBRIC R75）

- ① **哪里仍必须为 0**：除上表 5 项外，`--public` 下失败数必须为 0；反过来，上表「仍判红」列任一命中必须报红。
- ② **例外必须带 reason**：JSON 里每条豁免记 `{id, reason}`；无 reason 的豁免视为不合法（自检断言）。
- ③ **例外不得进入对外数字**：exempt 项**不计入通过数**，输出里单列计数；报告与 QUICKSTART 必须写明"`--public` 下的全绿不等于主仓全绿"。
