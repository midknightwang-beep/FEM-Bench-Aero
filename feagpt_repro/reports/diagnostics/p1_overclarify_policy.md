## 1. 事实一：唯一的硬错（与政策无关）

`L3_naca4412_wingbox` 的任务元数据（`tasks/tasks.jsonl` 实读）：

```

clarify_aliases         = ["n_ribs","翼肋","肋数","多少道肋","几道翼肋","肋的数量"]
```

## 3. 事实三：唯一被这条误登记打中的案例（就是它改变了 2×2）

`L3_naca4412_wingbox` 两模型的实际澄清文本：

| 模型 | 澄清文本 | 现状判定 |
|---|---|---|
| glm | 「翼肋数量 `n_ribs` 未给出（题面仅说明若干翼肋等距布置），请提供具体肋数」 | **PASS**（clarify_ok） |
| ds | ①「…未给出具体翼肋数量 `n_ribs`，请提供肋的数量。」<br>②「题面未明确蒙皮长桁数量 `n_stringers_per_skin`，请提供每侧蒙皮长桁数；**若确实无长桁，请明确说明为 0**。」 | **FAIL**（clarify_wrong）← **因为②用了本族正确键** |

⇒ **C-040 里「唯一的任务级差异是 `L3_naca4412_wingbox`」这条叙事会消失，两模型在 legacy exam 上完全打平。** 这是必须由你拍板的原因。

## 4. 事实四：按语义判 over-clarify 不可靠（实测 4/4 假阳性）

我用「文本里提到了非 expected 的键名」当代理指标，L2 命中 4 条（glm 3 / ds 1）。**逐条看原文，4 条全是假阳性**：

> 「翼盒每侧蒙皮的长桁数量 `n_stringers_per_skin` 未给出（**题面给出了长桁尺寸 `stringer_height`/`stringer_thickness`/`stringer_kind`，但未给根数**），请提供该字段」

这不是在问 `stringer_height`，是在**引用已知条件解释为什么该问根数**——属于好的澄清措辞。

⇒ **任何「按语义/按是否提到别的键」判多问的判据，都会把这类正确行为判成错。** 这是「不罚」的核心依据。

## 7. 三个选项

### 选项 A（推荐）：修标签 + over-clarify「不罚但必须可观测」

- 改 `L3_naca4412_wingbox.clarify_wrong_keys`：`['n_stringers_per_skin']` → `['n_stringers']`
  （保留「错族键」这一概念：翼盒题问柱壳/板的 `n_stringers` 仍算错族；R70 已保证它不会吃掉 `n_stringers_per_skin`）
- RUBRIC 预注册：**over-clarify 不判 FAIL**；但 artifact 必须记 `n_questions` + `over_ask_keys`，**不进 TSR/SFR 分母**，单独作「澄清效率」指标报告
- 明确写边界：**L2 的「全问一遍」仍是已知缺口**，不进 TSR 之外任何数字，下一版若要做，须用「该字段在 gold 里是否真的未定」这类**可判**判据，不得用条数或语义近似

| 影响 | 数字 |
|---|---|
| ds legacy exam | 22/25 → **23/25** |
| glm | 不变 |
| L2 两模型 | **不变**（49/64、36/64） |
| 2×2 | only_glm 1 → **0**（两模型打平） |

**代价**：C-040 要 post-hoc 声明（R-A2）+ 重打分 + 旧数留档（D10）+ bridge；「唯一任务级差异」叙事要改写。
**风险**：L2 的退化解未被堵，需如实记为已知缺口。

### 选项 B：修标签 + 加「问句条数上限」（≤2）

- A 的全部 + 判据新增：`n_questions > 2` ⇒ FAIL（按 expected+1 定，单字段题允许「主问 + 一次必要性确认」）
- 好处：把 L2 的退化解堵住，政策真的可判（条数比语义可靠）

| 影响 | 数字 |
|---|---|
| ds legacy exam | 22/25 → 23/25 |
| glm | 不变 |
| **L2 glm** | 49/64 **不变**（它唯一超限的那条本来就 FAIL） |
| **L2 ds** | **36/64 → 28/64** |

**代价**：L2 ds 掉 8 条，且**全部落在单侧** ⇒ 读起来像按模型调阈值；同时会连带罚掉「孔板题同时问 hole_x/hole_y」这类合理情形。

### 选项 C：只修标签，政策登记为「未评估」

- 只做 A 的元数据修正，RUBRIC 不写 over-clarify 口径，只在 R19 边界里记「未预注册」
- 好处：改动最小、不引入新判据
- 代价：**问题继续挂着**；下次任何人动澄清判据都要从零再判一遍；且 L2 的退化解仍无记录

## 8. 推荐与理由

**推荐 A。** 三条理由都是可复核的事实，不是偏好：

1. **修标签是纠事实错误**，与 over-clarify 政策无关——「把本族正确键写成错族键」没有任何口径能自圆其说。
2. **语义判不可靠已被实测否掉**（4/4 假阳性）；**条数判的代价不对称**（glm 0 / ds 8）⇒ 两者都不适合做成硬判据。
3. **A 的数字变化可完整解释**（1 条题翻转），而 B 的额外 8 条下跌无法与「模型变差」区分——这正是 R-A1「一个任务只改一个变量」要防的事。**B 应该单独立项**，先预注册、再跑、且必须给 bridge。

★ **A 与 B 都不属于「让自己好看」**：A 里那 +1 是修事实错误带来的；如果同时做 B，方向是 −8，两者方向相反，正好说明不是在择优。
