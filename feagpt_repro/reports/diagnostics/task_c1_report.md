## 5. ★ 更正 T-B1 的一条错结论：D-7 不存在

T-B1 报告里写「环境类失败 `return 2` 没传到退出码（实测 `rc=0`）」—— **是我的测量错误**。

```bash
# 当时的测法（错的）：$? 是 tail 的退出码
"$PY" score_baseline.py … 2>&1 | tail -3; echo "rc=$?"     # → 0

# 最小复现
"$PY" -c "import sys; sys.exit(2)" 2>&1 | tail -3; echo $? # → 0
"$PY" -c "import sys; sys.exit(2)" >/dev/null 2>&1; echo $? # → 2
```

不用管道实测：缺数据跑 `score_baseline.py` ⇒ **`rc=2`**。`sys.exit(main())` 三个脚本都有、一直是对的。
**D-7 无需修，且「CI 无法用退出码判断成败」这句话是错的。**

已就地更正 `task_b1_report.md`（保留原文 + 划掉错误值 + 写明测法），并把它列为**本轮的自我修正**。

> 同族错误本轮**又复发一次**：分节用的 `echo "=== 向 3 ==="` 夹在被测命令与 `$?` 之间，又读到 0。
> ⇒ **`$?` 必须紧跟在被测命令后面，中间不能有任何命令**（连一句 echo 都不行）。

## 5.2 对 D-3（行尾）的实测补充 —— **B-1 的结论是对的，但当时没说全**

写文档时为了给第三方一句「到底该怎么办」，我又把行尾问题实测了一遍。**B-1 的 D-3 机理描述是准确的**
（580 个一致 / 931 个断裂，本机 CRLF 的 clone 后仍 CRLF⇒一致、本机 LF 的 clone 后变 CRLF⇒断裂），
本轮补上的是**另一侧**：

| 配置 | `tasks/tasks.jsonl` 的 sha256 | `S-57`（卷指纹闸） | 负控 |
|---|---|---|---|
| 默认 clone（Git for Windows，`autocrlf=true`） | `caf0f6c3…`（= 权威值） ✅ | **绿** | 66/69（3 红，全是 sha） |
| `git config core.autocrlf false` + 重新 checkout | `6e7437b1…` ❌ | **红** | 68/69（1 红） |

**结论：两侧各有一批锚点** ——
关掉 autocrlf（得到全 LF）会弄坏 **CRLF 那一侧**（卷指纹 `caf0f6c3` 立刻变 `6e7437b1`，`S-57` 转红）；
打开它（得到全 CRLF）会弄坏 **LF 那一侧**（`S-59` 的修正表 sha 对不上）。
⇒ **不存在任何一种统一配置能让全部锚点同时成立**。这正是档 2（`.gitattributes` + 统一行尾 + 重算全部锚点）必须单独立项的原因 —— 它不是「顺手加个文件」，而是**一次性全链重新封存**。

**本轮唯一可交付的补救是「把话说清」**：已写进 `FEM-Bench-Aero/DATA.md` §6.1 与 `QUICKSTART.md` §6 ——
按**目的**分三档告诉第三方该在意什么：要验证数字 ⇒ 什么都不用管（判分不校验 sha，实测 `23/25` 逐字可复现）；
要跑全套自检 ⇒ 先 `npm install`，其余 sha 红项当已知限制读；要全绿环境 ⇒ 等档 2。

> ⚠️ 我在这一节里**一度判错**：初读实测结果时以为「B-1 的方向反了（本机是 CRLF 而 clone 是 LF）」，
> 于是准备写一条"更正"。回去核对 B-1 原文后确认**它写对了**，是我的记忆串了。
> ⇒ 又一次印证：**改别人的结论之前，先回去读原文，别读自己的回忆。**

只是这次的"没有工具读的东西"是**提交内容本身**。

**怎么发现的**：做完提交后照 T-B1 的教训去 clone 里复核（「clone 里才见真章」），
