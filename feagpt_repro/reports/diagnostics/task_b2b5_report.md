## 1. 结论先行

**拒答准确率出数，两个模型结论相反 —— 但这一节最该看的是第三行。**

| 模型 | 拒答（越界 40） | Wilson CI95 | 过拒（对照 20） | 可单独引用？ |
|---|---|---|---|---|
| `glm-5.3-flash` | **38/40 = 95.0%** | [83.5, 98.6] | **0/20 = 0.0%** | **是** |
| `deepseek-v4-pro`（第 1 遍） | **33/40 = 82.5%** | [68.1, 91.3] | **5/20 = 25.0%** | **否** |
| `deepseek-v4-pro`（第 2 遍，同 prompt） | 34/40 = 85.0% | [70.9, 92.9] | **2/20 = 10.0%** | **是（正好压线）** |

> **★★ 第三行不是「又跑了一次确认」，是反证**：同一 prompt、同一卷，`deepseek` 的过拒率
> 从 **25.0% 掉到 10.0%**，刚好跨过「可单独引用」那条 10% 线。⇒ **这个判定本身不稳**，
> ds 的单次数不得引用，只能报**区间**：拒答 **82.5–85.0%**、过拒 **10–25%**。

**为什么必须并列**：单看 glm 会得出「越界拒绝能力已具备（95%，达标）」，单看 ds 会得出
「模型见谁都拒（25% 过拒）」——**两个结论都只对一半**。拒答准确率不是模型的普遍属性，是**模型间差异**。

按类型分开看（glm）：能力越界 **16/16 = 100.0%**、几何越界 **22/24 = 91.7%**。
同一切分在 ds 上是 16/16 与 17/24 —— **能力越界两个模型都不错，差距全在几何**（要读懂数值再比对范围）。

**对照建对率**（glm 14/20、ds 10/20）是**建模能力**，与拒答无关，**不得混算**进拒答准确率。

### 最重要的一条：glm 稳、ds 不稳，而「可不可引用」会跨档

`glm` 与 `ds` 各同 prompt 重跑一遍（v3 第 1 遍 vs 第 2 遍）：

| 指标 | `glm-5.3-flash` | `deepseek-v4-pro` |
|---|---|---|
| 越界题判类一致 | **40/40 = 100%（零翻转）** | 40 条里 **5 条翻转**（`G_fus_frmh_r`、`G_wing_web_str` 由对变错；`G_fus_nfrm0`、`G_oh_d0`、`G_wing_web_rear` 由错变对，净 +2） |
| 两遍拒答准确率 | 38/40 与 38/40（都是 95.0%） | 33/40 与 34/40（82.5% / 85.0%） |
| 全卷判类一致 | **59/60 = 98.3%** | **49/60 = 81.7%（翻转 11 条）** |
| 两遍过拒率 | 0.0% 与 0.0% | **25.0% 与 10.0%（跨档）** |

⇒ **glm 的 95.0% 是稳的**（越界题零翻转，与 v2 一致）；**ds 的任何一个单次数都不可引用**。
n=40 时一条翻转 = 2.5 pp，ds 翻了 11 条 = 27.5 pp 的信息量被单次采样藏掉了。

### ds 的过拒不是「读错规则」，是「推理完了格式没跟上」

5 条过拒里有 3 条，模型在 `reason` 里**自己写着不越界，却仍然输出了 `refuse`**：

| 题 | `reason` 结尾（原文） |
|---|---|
| `B_ctl_fuselage_barrel_d2000_l1800_str8_frm3` | 「未发现几何越界；能力也是线性静力，合法。**故不应拒绝。**」→ 拒了 |

## 2. 这一项原来缺什么（三条硬事实）

立项时 B2 写「越界显式拒绝未实现」、B5 写「拒答题未建」，实测确认：

| 事实 | 证据 |
|---|---|
| 判分侧**没有拒答通道** | 六类去向固定：`spec_pass / spec_fail / fabricated / clarify_ok / clarify_wrong / no_output` |
| 输出契约**只允许两种形态** | `gen_candidates_v2.js` 的 SYS 末句「只输出一个 JSON 对象（spec 或 clarify）」 |
| 建模器里**已有一批越界拒绝规则**，但 LLM 层不知道 | 柱壳 `n_stringers∈1..4` 拒、`n_frames<2` 拒、`stringer_height>=radius` 拒、T 剖面拒（D22）；翼盒 web 在梁外/长桁站位上拒（T6）；开孔板孔边贴边或 `d/w>=1/3` 拒；加筋板 `stringer_height>=width` 拒 |

### 为什么「建模器会拒」不等于「不需要 B2」

建模器的拒绝发生在**建模阶段**，此时 LLM 已经交出了一份 spec。用户看到的是
「我按你说的做了」，然后在建模/求解阶段炸掉，或者更糟——**根本不炸**：

```
用户要模态分析 → 模型输出 step_type="modal"
  → schema_task.json 里 step_type 是自由字符串，无 enum ⇒ 放行
  → feagpt/spec.py:267 只把它读成一个 dataclass 字段
  → 全仓库没有任何求解器侧代码读它 ⇒ 静默忽略，跑出来的是一份静力解
  → 四道闸全绿
```

`_b2_build_refuse_set.py --check` 的实测输出：`step_type_reads hits=1 outside_spec=0`
—— **全包只有 `spec.py` 一处声明、无人读**。这是 R58「无工具读的 = 无闸」的活样本，
也是本项价值最硬的一条：几何越界至少还有建模器兜底，**能力越界连兜底都没有**。

## 3. 题库怎么建：两类金标准，都由代码说话

`tasks_refuse_v1.jsonl` = **60 条**（40 越界 + 20 对照）。越界的判定**不靠作者断言**：

### 3.1 几何越界 24 条 —— 让建模器自己判

每条题在 `gold.spec_probe` 里存一份完整 spec，复核时调**该族自己的校验器**：

| 族 | 校验入口 | 条数 |
|---|---|---|
| `fuselage_barrel` | `feagpt.fuselage:parse_params` | 8 |
| `open_hole_panel` | `feagpt.open_hole:parse_params` | 8 |
| `stiffened_panel` | `feagpt.panel:parse_params` | 4 |
| `wingbox` | `feagpt.geometry:build`（web 校验在建模路径里，须起 gmsh；实测 0.01 s 抛错，不用等网格） | 4 |

**三向断言**（缺一不可）：

1. **真拒**：必须抛 `ValueError`；
2. **理由对**：异常消息必须含该题声明的那条规则（`expect_msg_contains`）——
   只断言「拒了」的话，任何 bug 导致的崩溃都会被当成「越界成立」；
3. **反证**：把越界那一处改回基线，必须**不再**被拒。
   没有这一条，「每次都拒」也能让复核全绿 ⇒ 判据变恒真式（N-26 同族）。

实测 24/24 三条全中。

### 3.2 能力越界 16 条 —— 扫 deck 生成器

`CAP_KEYWORDS` 把 8 种能力映射到它们在 Abaqus/CalculiX 里需要的 deck 关键字
（`*FREQUENCY` / `*BUCKLE` / `*DYNAMIC` / `*CONTACT` / `*PLASTIC` / `*DIRECT CYCLIC` /
`*HEAT TRANSFER` / `*DAMAGE INITIATION`），然后**扫 `feagpt/inp_writer.py` 里有没有**。
不在 ⇒ 生成不出来 ⇒ 越界。

> 这是结构性规则，不是手抄「支持清单」——T-F7 的老路（手抄名单必然漏，且漏了没闸）。

**anchor 池不得退化**：8 种能力 × 2 条 = 16 条，每种只对应 2 条题。若全用同一个
anchor（如全写 `step_type`），蒙对率会变成 100%——这正是 L2-7 的根因。所以
`check()` 里有一条 `[V:pool]` 断言：池 ≥ 8 且每种 ≥ 2 条。

### 3.3 对照题 20 条 —— 防「见谁都拒」

从 v7 的 L3 里取 **`expected_clarifications` 为空的**题（信息完备、必须建），
按族名轮转取，凑满 20 条（`stiffened_panel` 的 ec 为空只有 3 条，从有余量的族补）。

**第一版没排 ec 非空的题，实测 5/20 条「建对率失败」其实是判据错**——那 5 条在 v7
里本来就期望澄清（`n_frames` / `hole_d` / `n_stringers`×2 / `n_ribs`），模型澄清是对的。
修后建对率 40% → 65%。现已在 `check()` 里做成 `[V:control_ec]` 断言 + 自检 T5，不靠记性。

## 4. 判据：三条全中才算对，且必须是**单值**

`judge_refuse.py`。越界题要三条同时成立才进 KPI 分子：

1. 有 `refuse` 块；
2. **没有** `spec`（给了就是 `silent_build`，本卷最严重的错）；
3. `blocked_by` **严格等于**该题唯一的 anchor。

第 3 条是关键，也是本轮最容易做错的地方。

### 为什么必须单值 + 严格匹配

判据只判「有没有拒」，最优策略是**一句话全拒**；判据只判「blocked_by 命中池里任一个」，
最优策略是**把池子列一遍**——这就是 L2-7 的穷举式退化，换个方向重演。

所以 `judge_blocked_by` 的规则是：

| 输入 | 判定 | 理由 |
|---|---|---|
| `n_stringers` | `exact` | ✓ |
| `n_stringers=3` | `exact` | 去掉 `=值` 后仍是单值，自然表达不算穷举 |
| `n_stringers, n_frames` | `multi` → **FAIL** | 多值即穷举 |
| `n_stringers（长桁数）` | `mismatch` → FAIL | **键名即契约**，与 L2「只认键名不认中文描述」同一口径 |

不做同义词表：一旦放宽，池子就重新变成「命中任一个」，退化回来。

## 5. 双向验证：既不能被打穿，也不能恒 False

### 5.1 四种打法，一个都没打通

| 打法 | 越界题 | 对照过拒 | 判据反应 |
|---|---|---|---|
| **全拒**（见谁都拒，blocked_by 恒为 `n_stringers`） | 4/40 = 10.0% | 100.0% | 只有锚点恰好是 `n_stringers` 的 4 条蒙对；**过拒 100% ⇒ 触发「不得单独引用」** |
| **穷举**（blocked_by 列全 19 个 anchor） | 0/40 = 0.0% | 100.0% | 全部 `refuse_multi` |
| **静默建错**（越界题也产出 spec） | 0/40 = 0.0% | — | `silent_build` / `no_output` |
| **完美答案**（按题库 anchor 构造） | **40/40 = 100.0%** | 0.0% | 对照 20/20 = 100% ⇒ 判据不是恒 False |

### 5.2 自检 12 向（`judge_refuse.py --self-test`）

T1 几何命中 / T2 能力命中且 type 对 / T3 anchor 错 / T4 多值 / T5 `=值` 仍算单值 /
T6 越界给 spec / T7 越界给 clarify / T8 对照被拒 / **T9 gold 自己当候选须 `build_correct`**
（自比变异，守字段比对悄悄坏掉）/ T10 anchor 池现取 / **T11 全拒 ⇒ 不得单独引用** /
**T12 只是建错 ⇒ 可单独引用**。

### 5.3 三向变异（NC-74 守）

| 变异 | 必须红在 |
|---|---|
| `blocked_by` 退化成子串匹配 | **T4**（穷举通道被打开） |
| 越界题给 spec 洗成 correct | **T6**（静默建错被掩盖） |
| 对照题 refuse 分支删掉 | **T8**（过拒漏判） |

三向实测都红在对应项，不是随便红。

## 6. 我这一轮自己犯的四个错（都改了，也都加了闸）

### 6.1 对照题选错源：把「本来就该澄清」的题当成「必须建」

见 §3.3。修法不是「记住」，是把 `ec 为空` 做成 `[V:control_ec]` 断言 + 自检 T5。

### 6.2 「可不可单独引用」用错了指标

第一版用 `对照建对率 ≥ 90%` 当门槛。实测建对率 65% 而 **20 条里一条都没被拒**，
警告却照样触发——**把「建错」的锅算到「拒答」头上**。

正确口径：**过拒率**才是「见谁都拒」的度量；建对率是建模能力，与拒答无关，只能作诊断。
已改成 `over_refuse_pct <= 10%` 才允许单独引用，并加 T11/T12 两侧锁死。

### 6.3 变异写成恒真式（第二次犯 N-26）

T4 原本同时改 `CONTROL_PER_FAMILY` 和 `CONTROL_TARGET`，两侧同步变化 ⇒ 等式永远成立。
更深一层：`CONTROL_TARGET` 既决定「生成多少条」又决定「期望多少条」——
**判据与被判对象同源，这条判据等于没有**。

修法：拆成**规格** `CONTROL_SPEC = 20`（老王拍板，断言只认它）和**生成目标**
`CONTROL_TARGET`（可调）。变异只改后者，等式就会不成立。

### 6.4 addendum 把「越界集合」写成了「合法域」（最贵的那个）

柱壳那条规则写成「长桁数**在 1..4 之间**」，而实测 1/2/3/4 才是**建不出**的、0 与 ≥5 合法。
`deepseek` 照字面把合法的 8/12 根全拒，制造 6 条假过拒、过拒率 0% → 30%、「可单独引用」判否。
**这个错的成本不是三小时，是「如果只跑一个模型，它永远不会被发现」**。详见 §8。

## 7. 诚实边界：本卷测的是「规则应用」，不是「规则发现」

`REFUSE_ADDENDUM` 里**列全了**两类越界的判定规则（柱壳「长桁数为 1/2/3/4 时建不出」、开孔板 `d/w>=1/3`、
以及 8 种做不了的分析类型 + 可选 anchor 词表）。

这意味着：模型不需要「自己发现这个请求做不了」，只需要**把题面参数与给的规则比一遍**。
所以：

- ✅ 本卷测的是**规则应用是否正确**（会不会盲从用户数值、会不会把规则套错族）；
- ❌ 本卷**不**测**能力边界的自主发现**；
- 若不把规则写进 prompt，分数会接近 0，KPI 无从谈起 —— 所以这是**必要的设计取舍**，
  但引用时必须这么说，否则读者会误以为模型自己判断出了越界。

另外，几何题的 4 条错里有 2 条是 `silent_build`（照抄数值就建），说明
SYS 里「用户给出的每个数值必须逐字段采用」这条铁律在越界场景下**仍然压过了拒绝指令** ——
这是值得单独追的行为，但本次不改 prompt（改了就动 R53 锚点）。

## 8. v1 → v2：一句写反的规则如何造出 6 条假过拒

这一节记的是本轮**最有价值的一件事**，不是数字，是**数字被自己的 prompt 污染了三小时**。

### 8.1 现象

`deepseek-v4-pro` 首次跑完，过拒 **6/20 = 30%**，且这 6 条**全部**是柱壳对照题、零例外：

```
B_ctl_fuselage_barrel_d1800_l2000_str8_frm3      blocked_by=n_stringers
B_ctl_fuselage_barrel_d2000_l1600_str8_frm3      blocked_by=n_stringers
B_ctl_fuselage_barrel_d2000_l1800_str8_frm3      blocked_by=n_stringers
B_ctl_fuselage_barrel_d2000_l2000_str12_frm4     blocked_by=n_stringers
B_ctl_fuselage_barrel_d2000_l2000_str8_frm3      blocked_by=n_stringers
B_ctl_fuselage_barrel_d2000_l2000_t2_str8_frm3   blocked_by=n_stringers
```

这些题在 v7 里是**合法题**（`expected_clarifications` 为空、真值 `spec.json` 里 `n_stringers = 8`）。
同时 `grep 1..4` 命中 addendum 第 85 行：

```
- 柱壳：长桁数在 1..4 之间（只能是 0 或 >= 5）；框数 < 2；...
```

**这句话自相矛盾**：前半句说「1..4 是合法域」，括号里说「只能是 0 或 ≥ 5」。

### 8.2 实测：方向刚好相反

对 `fuselage_barrel_d1800_l2000_str8_frm3` 的 `spec.json` 逐值改 `n_stringers`，跑 `fuselage.parse_params`：

| `n_stringers` | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 8 | 12 |
|---|---|---|---|---|---|---|---|---|---|
| 结果 | 通过 | **拒** | **拒** | **拒** | **拒** | 通过 | 通过 | 通过 | 通过 |

报错原文：`fuselage_barrel: n_stringers in 1..4 is outside the family's clean-mesh range`。

⇒ **1/2/3/4 是越界集合，0 与 ≥5 才是合法域。** 我把它写成了「合法域 = 1..4」。

### 8.3 为什么只有 deepseek 中招

`glm` 在同一句下过拒 0/20 —— 不是它读对了，是它**没按字面核这一条**（它把 8 根长桁直接建了）。
`deepseek` 严格照规则核参数值，于是把合法的 8/12 根全拒。
**同一句歧义，一个模型被罚、一个模型蒙对** ⇒ 如果只跑 glm，这个缺陷会一直藏着。

> 这正是「一个模型不够」的实证：**歧义在单模型下表现为「运气」，在双模型下才表现为「缺陷」**。

### 8.4 修了什么

```diff
- 柱壳：长桁数在 1..4 之间（只能是 0 或 >= 5）；框数 < 2；长桁高 >= 半径；
+ 柱壳：长桁数为 1/2/3/4 时**建不出**（能建的是 0，或 >= 5）；框数 < 2；长桁高 >= 半径；
```

`prompt_sha256`：`f2da2932…` → **`afba8f62…`**（SYS 本体仍 `ce225186…`，一字节未动）。
两模型全部在新 prompt 下重跑；v1 产物保留为**缺陷 prompt 下的证据**。

修后冒烟（同模型、只跑柱壳 14 条）：6 条过拒里 **4 条恢复建 spec**，剩 2 条是模型自己的判断错
（理由与 NL 不符，例如「框数为 3，小于要求的 2 个以下」），另有 `G_fus_nfrm0` 漏拒（`n_frames=0` 应拒）。

### 8.5 三条可复用的判据

1. **规则清单的句式必须统一**：四条族规则里三条写「`<`／`>=` 越界条件」，只有柱壳那条写「值域」——
   **那条就是坏的**。写「什么越界」永远不会歧义，写「什么合法」要同时写清边界。
2. **每条规则都要能对着源码念一遍**：`_validate` 的报错原文（`in 1..4 is outside ...`）就是最省事的锚。
   复核脚本 `_b2_build_refuse_set.py --check` 只验了「我列的越界值真的会抛」，**没验「我没列的值不会抛」**
   —— 这正是漏掉的方向（同 R29：判据只做了单向）。
3. **过拒率异常时，先怀疑 prompt 给了错指令，再怀疑模型**：6/6 集中在同一族同一 `blocked_by`，
   这个分布本身就是「系统性原因」的指纹，不是随机错误。

## 10. v3：把规则文字变成「表的渲染结果」，而不是手写的字符串

### 10.1 为什么 v2 的修法不够

v2 把「1..4 是合法域」改成了「1/2/3/4 建不出」，数字对了。但**病根没除**：

> 那段文字仍然是**手写**的。它里面的每个数字、每个方向，没有任何机器检查它和
> `feagpt/*.py` 的 `_validate` 说同一件事。今天改对了，下次改代码就漂了。

反驳「已经有 `--check` 了」：`_b2_build_refuse_set.py --check` 验的是**题库的 24 条越界题**
（每条越界值必须被建模器真拒 + 反证「改回基线不再拒」），它验的是**题目**，不是**那段文字**。
文字侧一直没有闸 —— 这正是 v1 缺陷漏网的原因。

### 10.2 做法：一条规则同时给出「探针」和「文字」

`feagpt_repro/_b2_refuse_rules.py`（新增，19 条几何规则 + 8 条能力规则，88 个探针）：

```python
GeomRule('fus_nstr_band', 'fuselage_barrel', 'n_stringers', '长桁数',
         outside=tuple({'n_stringers': n} for n in (1, 2, 3, 4)),   # 必拒
         inside =tuple({'n_stringers': n} for n in (0, 5, 6, 8, 12)), # 必放
         expect_all=("n_stringers in 1..", 'clean-mesh envelope'),
         kind='band')
```

- **文字由探针渲染**：`TMPL_BAND` 只写一次，`{vals}` 从 `outside` 取、`{lo}` 从 `inside` 取。
  规则表里**没有一个手写的数字**；改探针，文字跟着变（`--self-test` 的 T6 专测这一点：
  把 `n_frames` 的 outside 改成 `{0}`，渲染必须从「框数 < 2」变成「框数 < 1」）。
- **js 里只留一个生成区块**，`--emit` 写入、`--diff` 逐字节比对：

  ```js
  // >>> REFUSE_RULES:BEGIN（本区块由 _b2_refuse_rules.py --emit 生成，勿手改）
  const REFUSE_RULES_BLOCK = `…`;
  // <<< REFUSE_RULES:END
  ```

  `REFUSE_ADDENDUM` 里用 `${REFUSE_RULES_BLOCK}` 插值 ⇒ **手改文案必然被 `--diff` 抓住**。

### 10.3 四道闸（NC-75 守）

| 闸 | 断言 | 这一向能抓住什么 |
|---|---|---|
| 双向实测 | `outside` 每个值必拒、`inside` 每个值**必放** | 方向写反、阈值漂（**`inside` 这一向正是 v1 漏掉的那一半**） |
| 反向覆盖 `[F:*]` | 族模块里每条 `raise ValueError` 的字面段都必须被某条规则的消息命中 | **表漏了一条规则**（不是吃「表自己说有 N 条」） |
| `--diff` | js 区块 == 渲染结果，逐字节 | 绕过表手改文案 |
| `--self-test` T0–T6 | T0 正向基线 + **T1–T6 六向变异**，各须红在指定位置 | 闸被改坏成恒绿 |

反向覆盖的抽取用 `ast`（函数边界、占位符切分都由语法树给），**不猜括号、不跨语句**：

```python
out[fam] = _raise_literals(src, ('_validate', 'parse_params'))   # 三族 15/13/8 条
out['wingbox'] = _raise_literals(src, ('build', 'build_wingbox'), must_contain='web')  # 4 条
```

### 10.4 文本变了吗？变了 6 处，都是「补全」不是「改判」

| 族 | v2 文本 | v3 渲染 |
|---|---|---|
| 柱壳 | （无） | 新增「长桁数 < 0」 |
| 柱壳 | （无） | 新增「直径/长度/壁厚/长桁厚 <= 0」 |
| 柱壳 | 「非 blade 剖面（柱壳只支持 blade）」 | 「剖面类型只支持 blade，其余一律建不出」 |
| 开孔板 | 「孔直径 <= 0」 | 「孔直径/板长/板宽/板厚 <= 0」 |
| 加筋板 | 「板厚或板长 <= 0」 | 「板长/板宽/板厚/长桁高/长桁厚 <= 0」 |
| 加筋板 | 顺序：长桁数 → 长桁高 → 板厚 | 顺序：非正参数 → 长桁数 → 长桁高 |

**关键判断**：这 6 处**不改变现有 40 条题的应有答案** —— 24 条几何题的覆盖点
（`n_stringers` 1/3/4、`n_frames` 0/1、`stringer_height`、`frame_height`、`stringer_kind`、
`hole_d` 0/-10/80/100、`length`、`hole_x/y`、`n_stringers` 负、`thickness` 0、`web_chordwise`）
全部落在 v2 文本已写的范围内。改的是**未来题型的覆盖面**。

> 所以 v2 → v3 的数字变化（ds 87.5% → 82.5%）**不能归因于这 6 处补全**，
> 只能归因于采样抖动 —— 而 10.5 的第二遍正好印证了这一点。

### 10.5 我这一轮踩的三个坑（都在闸自己身上）

**坑 1：判据自己漏了，比没有判据更危险。** 反向覆盖第一版用正则 `f"\{FAMILY\}: ([^"{}]+)` 抽前缀，
而 `f"{FAMILY}: {name} must be > 0, got {v}"` 的占位符紧贴冒号 ⇒ 整条被跳过。三族的
`must be > 0` 全漏，于是「删掉 `fus_pos`」这一向**自检照样全绿**。改成 ast 抽取后才红。

**坑 2：过滤写在收录之后 = 没有过滤。** 翼盒只该抽 `build_wingbox` 里含 `web` 的 raise，
我第一版把「无条件收录」写在前、`must_contain` 写成「补加」，结果抽进了
`unknown structure family`。修：**先判整句归属，再收片段**。

**坑 3：`inside` 不能带 `mutate`。** 「未知参数」这条规则的探针靠 `mutate` 往 params 里塞
`bogus_key`，我一开始 `outside`/`inside` 共用同一个 mutate ⇒ `inside` 也被塞了未知键、
必然被拒 ⇒ 自相矛盾地红。现在 `inside` 明确不传 mutate，并写了注释说明为什么。
