FEM-Bench-Aero 数据集生成方案 v2

v2 修订：优先打 A 建模集 + 把结构形式从 1 种扩到多种（等直翼盒 → 加筋壁板 / 机身柱壳段 / 后掠锥形翼 …）

三子集仍在，A 优先 结构形式：1 → 5+ 种典型 判定升到 3+1 关（新增语义关卡） 双求解器（CalculiX + Abaqus） 2026-10-02 v2

修订说明：v1 → v2 改了什么

v1 的方案是「三类子集并行推进」。新需求两条：① 先只打 A 建模集 ② 覆盖更多飞机典型结构形式。 这两条各自都会改计划，叠在一起改动更大。三条结论先摆这儿：

结论说明
① 流程可以砍掉 2 步 只做 A 类，则 S2 场量导出（应力列）与 S3 云图渲染这两步整个不需要—— 那是 B 解读集的活儿。A 类要的是「四件套齐全 + 可判定」。原本排在最前面的「补应力列」从 P0 降到 P2。
② 原来的 M1 要换内容 v1 的 M1 是「补应力列 + 补 .msh」。现在应是「补 .msh（四件套）+ 结构族抽象」。 而结构族抽象是大改——它是覆盖多结构形式的前置条件（见 §4）。
③ 判定要加第 4 关 结构形式一多，「跑通」就不等于「建对了」。必须新增语义关卡： 生成的模型是不是真的是那个结构（几个肋、几根长桁、在不在正确位置）。这是 A 类独有的判据（见 §7）。
一句话：v1 的骨架（三子集 / 七步 / 三关 / 双求解器）不变，但「先做哪个、按什么顺序、判定什么」全变了。 下面 ★ 标记的三节是本次新增/重写的核心。

0 · 为什么要自建（结论未变）

前两轮调研结论：通用 FEM + LLM 的地基已够用，缺的是「飞机结构语义 + 试验真值」。 本地三个公开集都落在这个缺口上——都没有壳、长桁、翼肋：

本地公开集体量值得沿用的范式短板许可
FEM-Bench85 MB，25–33 任务任务 = 可执行函数 + pytest 判定 教材级：梁/桁架/单元矩阵；无壳/长桁/框/复材MIT（代码）
StructuralEval74 MB，25 题图 → JSON 模型 → 求解器验证 闭环 只有梁/刚架/桁架CC BY-NC ⚠️
ALL-FEM1.8 MB，1005 条instruction → 代码 语料格式 FEniCS 变分，与工程壳单元链路不通以 HF 页为准
而这条链路已经能造出它们没有的东西：双求解器后端，同一几何两代码各算一遍并交叉验证 7/7 PASS； 已跑通翼盒、翼肋、翼梁、竖式长桁。
但——只有一种结构形式。这正是 v2 要解决的（见 §3）。

2 · 聚焦 A 建模集：三处具体修正 ★

2.1 流程瘦身：7 步 → 5 步（A 类专线）

S0 采样→ S1 链路跑→ S2′ 四件套归档→ S3′ 3+1 关门禁→ S4′ 打包索引→ S5′ 分层划分

被砍掉的（保留给 B 类）： 场量导出 云图渲染

直接后果：原本排第一的「补应力列」不再是当务之急。A 类只消费 results.json 里的标量 （max\|u\| / max vM / 位置）——这些早就有了。逐节点应力是 B 类解读集的输入，等打 B 时再做。

2.2 A 类真值要加「语义清单」

结构形式一多，「跑通」和「建对」就分家了。比如让模型建「5 个翼肋 + 3 根长桁」的翼盒， 它可能建出一个能跑通、网格也好、但只有 4 个肋的模型——三关门禁全过，语义是错的。

所以 A 类的真值里必须带上可核对的语义清单：

{
  "case_id": "wingbox_rib5_str3_F2_L1",
  "structure": { "family": "wingbox", "params": { "n_ribs": 5, "n_stringers_per_skin": 3, ... } },
  "expected_topology": {                    // ← 新增：语义真值
    "n_ribs": 4, "n_spar_webs": 4,
    "n_stringers_upper": 12, "n_stringers_lower": 12,
    "n_skin_faces": 32, "n_surfaces_total": 69
  },
  "expected_scalars": { "n_elements": 7517, "min_jacobian": 0.5228,
                        "max_disp_mm": 2.2194, "max_von_mises_MPa": 9.83 },
  "tolerance": { "max_disp_pct": 2.0, "max_vm_pct": 2.0, "minJ_floor": 0.30 }
}

好消息：这些数现在就能从 _collect_groups() 直接拿到—— 链路本来就把每个面归到了逻辑组（upper_skin/front_spar/stringers_upper…）， 只是以前没人拿它当判定依据。这是「零成本升级」。

3 · 结构形式扩展路线图 ★

3.1 现状：链路只有「一种」结构

当前 build_wingbox() 产出的永远是同一个东西：

NACA 翼型的 等直 翼盒 = 上下蒙皮 + 前后梁腹板 + N 个平面翼肋 + M 根竖式长桁

「等直」这两个字是关键——见 §4.2 的诊断：只要截面沿展向变化（锥形/后掠），现有面分类器直接失效。 所以扩展结构形式不是「多写几个 if」，是要动架构。

3.2 候选结构形式清单（按可行性排序）

每一行给：几何上新增什么 / 链路要动什么 / 代价 / 我的优先级建议。P0 = 建议第一批就做。

#结构形式几何上新增什么 链路要动什么代价优先级
T1后掠 / 锥形翼盒
真实机翼的基本特征		 翼尖弦长 ≠ 翼根；前/后梁沿展向偏移（tip_chord_ratio、sweep_deg） 面分类器必须换机制（§4.2）；根肋判定要跟着变 中P0
T2加筋平板壁板

T3机身加筋柱壳段

语义价值最高
为什么 T1 / T2 排 P0：
· T1 是「机翼」这条线从玩具走向真实的分水岭——真实机翼没有等直的。不做 T1，机翼族都是同一个模子。
· T2 是性价比之王：平板几何实现最简单，但它同时是 试验数据最丰富的形式（机身/机翼壁板压缩试验，FAA EMST 那类数据全是这个）， 意味着未来接「试验真值」这条路最容易从 T2 走通——而试验真值正是调研报告说最缺的东西。

3.3 建议的三批推进

第 1 批（立即可做）

T2 加筋平板壁板
T5 长桁截面族（blade/T/hat）
理由：改动小、复用现有长桁逻辑、能立刻验证「结构族」这套架构

第 2 批（架构验证后）

T1 后掠 / 锥形翼盒
T3 机身柱壳段
理由：T1 需新分类器机制先落地；T3 需要新的 BC/载荷类型

第 3 批（语义升级）

T4 开口加强 · T6 多闭室
T7 复材层合
理由：T7 要动双求解器的壳截面卡，工作量最大但语义价值最高
需要你拍板的一件事：T7 复材层合要不要进第一批？ 它是「飞机结构语义」里分量最重的一块（真实机翼/机身早就是复材了），但要改两个求解器的截面卡， 是这批里唯一「大改动」项。我的建议是不进第一批——先把「结构族 + 语义判定」用 T2/T5 验证扎实， 再上复材。如果你认为复材是刚需，我们就把它提到第 2 批。

4 · 架构必需改动（覆盖多结构形式的前提）★

这三处不改，「多结构形式」就只是一个想法。都是结构性问题，不是加参数能绕过的。

4.1 结构族抽象：从「一个函数」到「一族 builder」 M2 已落地

现在 build_wingbox() 直接写死了翼盒拓扑。spec 里也没有「我要什么结构」这个字段。

# spec 新增
@dataclass
class StructureSpec:
    family: str = "wingbox"   # wingbox | stiffened_panel | fuselage_barrel | ...
    params: dict = ...             # 族内参数（各族不同，由族自己解释）

# geometry 侧改成注册表
BUILDERS = {"wingbox": build_wingbox, "stiffened_panel": build_stiffened_panel, ...}

def build(gmsh, spec, step_path=None):
    return BUILDERS[spec.structure.family](gmsh, spec, step_path)

好处：pipeline / meshing / inp_writer / post 一行都不用改——它们只认 GeometryResult（surfaces 逻辑名 + span/chord + 包围盒）。 这个抽象其实现在就成立了，是既有设计白送的红利。

4.2 面分类器必须换机制（最硬的一处）

现在 _classify_faces() 靠包围盒反推：dz≈0 → 肋；dx≈0 → 梁/长桁；其余 → 蒙皮。 为验证它的余量，我实测了当前翼盒每个面的弦向跨度：

逻辑组面数dx 最大 (mm)dz 最大 (mm)判据命中
upper_skin4450.0000500.0000else → 蒙皮
lower_skin4450.0000500.0000else → 蒙皮
front_spar40.0000500.0000dx ≤ 1e-6 → 梁
rear_spar40.0000500.0000dx ≤ 1e-6 → 梁
ribs / root4 / 1450.00000.0000dz ≤ 1e-6 → 肋
判据是「二值」的：梁的 dx 精确等于 0，蒙皮是 450——中间没有过渡。 这意味着它现在很稳（余量 6 个数量级），但一旦截面沿展向变化，梁的 dx 从 0 变成非零中等值， 判据立刻翻转：梁面（dx > 1e-6、dy 也非零）会掉进 else 分支被归成蒙皮。

结论：这不是「不够鲁棒」，是结构上只能服务等直几何。T1（后掠/锥形）一来就崩。

改法：放弃「事后从包围盒反推」，改成建面时就打标—— M2 已落地

  1. 构建每个面时，同时记下 face_tag → 逻辑名（用 dict，或用 gmsh.model.addPhysicalGroup）；
  2. fragment 时保留 outDimTagsMap（现在代码里明写「deliberately ignore the map」）， 从映射把每个输出面回溯到它的输入面，逻辑名继承下来；
  3. 包围盒判据只留作交叉校验（打标结果与几何特征对不上就报警），不再当唯一依据。

这是 v1 方案里没写、但 v2 必须解决的一处。好在它不影响现有算例的数值—— 改完拿 9 条种子算例回归，分组必须逐位一致。已达成：9/9 逐位一致； 探针实测 outDimTagsMap 长度 == 输入实体数、每面被恰好一个输入认领、与包围盒零分歧。

4.3 边界条件与载荷要跟结构族绑定 M2 已铺路（bc_groups 声明）

结构族约束位置载荷现在支持？
翼盒根部肋（z≈0）翼尖集中力✅
加筋壁板四边（简支 / 固支）面内轴压 / 剪切 / 侧压❌ 要加
机身柱壳段两端环框内压 + 弯曲 + 剪切❌ 要加
后掠翼盒根部肋（斜的）翼尖集中力⚠️ 根肋判定要泛化

现在 _tag_root_tip() 硬编码「z≈0 就是根」。壁板要按包围盒四边取， 柱壳段按两端环取。这属于族内部的事，放手让每个 builder 自己声明边界条件更干净。

6 · 生成流程（A 类专线，5 步 + 3+1 关）

S0

采样 —— 现在是「结构族 × 族内布局」两级

输入：结构形式清单 + 各族参数空间 + 种子 ｜ 输出：specs/*.json
变化：v1 是单族扁平笛卡尔积，v2 要先选族、再展开族内参数（见 §8）
S1

链路执行 —— 几何 → 网格 → deck → 双求解器

做法：pipeline.run()，两求解器各跑一遍
注意：Abaqus 必须用不隔离的 shell（pre.exe 要写 %TEMP%，被拦则固定 ~19 s 静默失败）
S2′

四件套归档

输入：算例目录 ｜ 输出：spec.json / .step / .msh / .inp + truth.json 骨架
要补：求解路径也写 .msh（现在只有 --mesh-only 写）
S3′

3+1 关门禁 —— 不过就不入集

关 1 网格：minJ ≥ 0.30，零三角（全四边形）
关 2 物理：静力平衡残差 < 1e-3 %
关 3 交叉：双求解器 max|u| 差 < 1 %，逐节点 vM 中位差 < 5 %
关 4 语义v2 新增：分组计数与 expected_topology 逐项一致（肋数、长桁数、面数…）
S4′

打包与索引

输出：MANIFEST.json（含 structure.family、spec 哈希、代码版本）
S5′

分层划分

做法：按结构族 × 几何族分层，同族只进一个 split（防「同族泄漏」）
对 B 类保留的两步： S2 场量导出 S3 云图渲染 —— 等 A 打牢、要打 B 时再接回来，改动很小（应力实测是逐节点现成的）。

7 · 质量门禁：3 + 1 关

关卡检查项阈值不过怎么办
关 1
网格		最小缩放雅可比 / 单元类型≥ 0.30 / 全四边形 丢弃，记 rejected.json；整族失败则回查参数
关 2
物理		静力平衡残差< 1e-3 % 丢弃。这是唯一独立于两个求解器内部约定的不变量
关 3
交叉		max\|u\| 两解之差 / 逐节点 vM 中位差< 1 % / < 5 % 丢弃。两个独立代码都对不上，不该进数据集
关 4
语义新M1 已落地		 拓扑计数（肋/长桁/梁/面数）与 expected_topology 逐项比对 精确相等 丢弃。能跑通但建错了——结构形式一多，这是最容易漏的一类错
关 4 为什么必须「精确相等」而不是给容差：拓扑是离散事实——5 个肋就是 5 个， 不存在「4.8 个肋」。给容差反而会放过真错（比如 5 个肋里少了 1 个）。
这也是 A 类区别于 B 类的地方：B 类的答案（2.2194 mm）天然有数值容差，A 类的结构计数没有。
落地形态（M1，见 §11.1）：判据是「由 spec 派生的应有几何计数 vs gmsh 实测计数」， 不是拿 design 跟自己比——那样等于没验。两个读数分开存进 truth.json， 比较器与生成器解耦。另有一道独立的「结果–网格同源」闸，专抓关 4 看不见的错配。

7.1 每种新结构形式必须自带「退化自检」

新加一种结构形式，怎么知道它实现对了？让它退化成已验证的形式：

新形式退化参数应还原为判定
T1 后掠 / 锥形翼盒sweep=0, tip_chord_ratio=1现有等直翼盒 分组与网格逐位一致（5144 单元 / minJ 0.6249 那套）
T2 加筋壁板曲率 → 0，与翼盒展开面比对平面 + 长桁解析解对照（板弯曲）
T5 长桁截面 hat → blade缘条宽度 → 0现有竖式长桁分组计数一致
T6 多闭室中间梁与后梁重合现有单闭室分组计数一致
这是「零错例」在结构扩展上的落地方式：新形式不是「跑通就算」，而是要能退回已验证的基准。 现有 9 条算例就是那个基准。不做退化自检，扩展结构形式就是在积累未验证的假设。

8 · 采样：结构族 × 族内布局

8.1 为什么要改成两级

v1 是单族（翼盒）的 7 轴笛卡尔积。多结构形式下，各族的参数根本不一样—— 翼盒没有「四边约束方式」，壁板没有「翼尖弦长比」。所以必须按族定义各自的参数空间。

8.2 结构族配额建议

结构族族内参数（轴）建议配额备注
wingbox
（含 T1 后掠/锥形）		 翼型数 / 弦长 / 肋数 / 长桁数 / 后掠角 / 梢根比~40% 最成熟的一族，可承接大部分样本
stiffened_panel 板尺寸 / 长桁数 / 长桁间距 / 截面形式 / 框数 / 边界条件~30% 性价比最高，且最易接试验真值

开口件 / 多闭室 开口尺寸位置 / 口框形式；梁数~10% 应力集中 / 多闭室扭转

规模建议：先按 9 条种子打样 → 每族扩到 40–60 条 → 全库 200+。 每条 ccx ~7 s、abaqus ~20 s；但结构形式变复杂后单条耗时会涨，放量前要重新实测一遍。

8.3 去重与平衡

  • 去重：spec 规范化哈希（族 + 族内参数）——同样参数不许出两条（v1 的笛卡尔积无去重，会出重复）。
  • 分层：按「结构族 × 几何族」分层，保证 test 里每族都有样本，且同族不跨 split。
  • 平衡：L1~L4 难度在各族内均匀分布，避免数据集被 L1（参数给全）刷满。

9 · 用途（本轮聚焦前两项）

U1 · 微调与评测「建模 Agent」本轮

「一句话 / 一组参数 → 能跑通且建得对的模型」。用于微调建模模型，或作为不改代码就能重跑的评测基准。

结构形式一多，这个数据集的价值就从「飞机壳」升级成「飞机结构族」—— 覆盖翼面 / 壁板 / 机身三类，对缺口①②的回应才真正成立。

U4 · 代码回归门禁本轮

立刻可用：改链路代码后跑一遍判定。基线是 5144 单元 / minJ 0.6249 / 2.3654 mm——动了就报警。

扩展结构形式时这一项价值更大：每加一族，都要保证老族一个数不动（退化自检就是干这个的）。

U2 · 结果解读子 Agent后续

「看场数据 / 云图 → 说出极值、位置、危险区」。FRAME 缺位后的替代品。依赖 A 的产物 + 需要补应力列与云图。

U3 · 模型更新监督信号后续

「响应变了 → 结构改了什么」。A 类的结构参数化天然能造对子（如 n_str 0→3：挠度 −6.15%）。

关 4 的判据按 §7 落地为「派生预期 vs 几何实测」，映射（等直翼盒族，n_ribs−1 个展向舱）：

梁面 = n_spars(n_ribs−1) ｜ 单侧蒙皮 = (n_str+1)(n_ribs−1) ｜ 长桁 = n_str(n_ribs−1) ｜ 肋 = n_ribs
壳面总数 = (n_spars + 2(n_str+1) + 2·n_str)(n_ribs−1) + n_ribs
M1 暴露的两个问题（已处理 / 已记录）：
  1. 根部肋被单列：BC 要打根部肋，它被单独放进 root 组，于是 len(groups["ribs"]) 对 5 肋箱体只得 4。若拿组面数当肋数，关 4 会系统性判错。 读回时把 root/tip 折回。
  2. spec 与几何会静默过期（关 4 抓不到）：7 条历史种子的 spec.json 写着 n_stringers_per_skin = 3，但那是从未生效的默认值，几何里没有长桁；用同一 spec 重跑会真的建出长桁，与归档结果对不上。⇒ 导出时增设「结果–网格同源」闸（重建网格节点数 vs 归档 n_nodes），并就地修正这 7 条 spec（3→0，归档结果本身是对的）。
结论：关 4（几何 vs 派生预期）和「同源闸」（结果 vs 网格）是两道闸，抓不同的错。只有关 4 不够。
已知问题（M2 已解决）：naca4412_wingbox 与 naca4412_wingbox_n_ribs5_chord1000 是同一模型 （model.msh 逐字节相同）。M2 按「物理删除冗余、保留基线」处理（删后者），数据集 9→8 条/树， 并把「同树内网格重复」升为硬闸。

13 · 执行摘要

一句话：新需求需要改计划，而且改得不小——但改的是「顺序和重点」，不是「骨架」。 骨架（三子集 / 双求解器 / 门禁思想）全部保留；变的是：A 优先、流程砍两步、判定加一关、M1 换成架构活。

  1. 只打 A 类 → 流程从 7 步瘦到 5 步：砍掉「场量导出」与「云图渲染」（那是 B 类的）。 连带把 v1 排第一的「补应力列」降到 P2——A 类只消费标量，那些早就有了。
  2. 覆盖多结构形式 → 必须先动架构，而不是先加 if。三处： (a) 结构族抽象（StructureSpec + builder 注册表）； (b) 面分类器换机制——实测证明现行「包围盒反推」判据是二值的 （梁 dx = 0.0000、蒙皮 450 mm），一旦后掠/锥形就翻转，梁会被误判成蒙皮； (c) 边界条件 / 载荷按族声明（现在硬编码「z≈0 是根」）。
  3. 新增「关 4 语义」且要求精确相等：结构形式一多，「能跑通」≠「建对了」。 A 类真值要带 expected_topology（几个肋、几根长桁、多少面）。好消息是这些数 _collect_groups() 现在就能给，属于零成本升级。
  4. 结构形式优先级：T2 加筋壁板 + T5 长桁截面 先打（改动小、复用现有逻辑）； 再 T1 后掠/锥形翼盒（需新分类器落地）+ T3 机身柱壳段；T7 复材层合价值最高但要改双求解器截面卡， 建议放后面——除非你认为是刚需。
  5. 每种新形式必须自带退化自检：如 sweep=0, tip_chord_ratio=1 必须还原成现有等直翼盒 （5144 单元那套）。这是「零错例」在结构扩展上的落地方式。
  6. 路线重排：M1 四件套+语义 → M2 结构族抽象+打标分类器（回归 9 条种子逐位一致） → M3 首批新形式 → M4 判定+索引 → M5 放量。顺序不能反：先让机制对，再让它多。
