## 由报告生成 PDF 与 Word 版本
- 需求：基于 .html 出 PDF（调整页面尺寸覆盖全部内容）、基于 .md 出 Word（覆盖全部内容）。
- 环境：本机无 pandoc/weasyprint(chromium缺失)/无浏览器；但存在系统 Microsoft Edge（`/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`）与受管 Python venv（`.../binaries/python/envs/default`，已装 python-docx/websocket-client/pypdf）。
- PDF 方案：`.html` 先转"打印版静态 HTML"（去掉侧边栏、展开全部 tab 面板、对比图预渲染为静态 CSS 条、JS 全删、加 `@page{size:A4 landscape}`）。关键坑：Edge 的 `--headless --print-to-pdf` 与 `--headless=new` 均**忽略 CSS @page 尺寸**（固定 US Letter 纵向）。改用 DevTools Protocol：`msedge --headless=new --remote-debugging-port=9222 --remote-allow-origins=*`，websocket 调用 `Page.printToPDF` 并显式传 `paperWidth:11.69, paperHeight:8.27`（A4 横向 297×210mm）、margin 0.394in、printBackground。→ 成功生成 13 页 A4 横向 PDF，内容全覆盖（含对比图 3.0/3.5/5 评分）。
- Word 方案：自写 Markdown→DOCX 解析器（python-docx），处理标题/表格/引用块(带左侧色条)/有序无序列表/加粗与行内代码、CJK 字体(Microsoft YaHei)、表头底纹、A4 纵向。关键坑：bullet 正则 `^- \s` 错误导致 `- foo` 行无法匹配、掉进普通段落分支且 i 不前进→**死循环**被沙箱杀掉；改为 `^[-*]\s` 且每个分支保证 i 自增后解决。→ 生成 152 段落 / 11 表格 DOCX，9 个章节(0–8)齐全。
- 验证：pypdf 抽取 PDF 文本查 21 个关键串全部命中；python-docx 校验 DOCX 章节标题齐全。
- 产出文件：`飞机结构FEA数据集调研报告.pdf`、`飞机结构FEA数据集调研报告.docx`（同目录）。可复用脚本：make_print_html.py、edge_pdf.py、md_to_docx.py。
