### 本轮最值钱的三条
1. **L1 的 100% 是闸严格度的影子**：所有 spec 题首轮结构校验**无一条通过**（glm 0/58、ds 0/61），首轮通过的清一色是**澄清题**（它们第 1 轮只输出 clarify，不进 spec 校验）。⇒ 它证明「错误反馈可读」，不证明「会建模」。
2. **首轮失败几乎全在两个可修点**：① `material` 的 `youngs_modulus`/`poisson_ratio`/`yield_strength` 在 v7 glm **58/59 条**缺失，而 schema 的 `properties.material.required` 是 5 个全 required、**SYS prompt 只写 `"material":{...}` 一个键没列**；② `gen_candidates_v2.js:40` 明写「网格键 size_chord/size_span（翼盒）、**size（板壳类）**」，而 `properties.mesh.required=[size_chord,size_span]` 是所有族、`size` **不在 properties 里** ⇒ **一因两果**：`size` 被拒 21 条 + `size_chord/size_span` 报缺失 21 条，按族核全是板壳类（open_hole 12 / stiffened 3 / barrel 6）。
3. **修复循环掩盖真问题**：`turns_histogram={1:5,2:57,3:2}` + `n_unresolved=0` 读起来「几乎没失败」，实际 59/64 条首轮都错。**闸做得越好，越看不出上游不同步。**

### 现场自纠四条（都是自检抓出来的）
1. **C5 判据漏「耗尽」分支**：写成 `turns == len(vh)+1`，被 `cfrp45s_d40`（3 轮全失败）判红。回读源码确认跑满不 break ⇒ 改双分支，且**更严**（还多抓「提前停止」）。
2. **C7 用错字段**：`per_task` 键名不统一（澄清题有 `expected`，spec 题没这个键）⇒ `fabricated` 那几条恰好「没有 expected 键」，被误判成形态不符。改用判分器自己的布尔 `ec`。
3. **★ C8 首版是恒真式**：`sum(Counter值) == len(items)` 按定义恒成立，任何未知类别都「闭合」，于是 `bad_closure` 那一向永远绿。改成「类别必须落在 `{spec_pass, spec_fail, fabricated}`」才真会红。与 N-26 同族。
4. **夹具不真**：夹具按 `turns-1` 造校验史，而真实的**耗尽**题是 `turns` 条 ⇒ 「好数据须绿」那一向被 C5 判红。判据没错，是夹具不真（T-D6 同族）。
