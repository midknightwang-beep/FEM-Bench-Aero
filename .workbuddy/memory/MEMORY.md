## 通用坑（每条只留问句与修法）

### A. 判据设计
- **★★★ 判据不能依赖顺序/位置/时间戳** ⇒ 问「**shuffle 一下数据集，这条还是这道题吗**」。
- **★★★「默认拒绝 + 手抄名单」必然漏**，名单里的「具体值」比名单本身更危险 ⇒ 结构性规则 + 一条**不读名单**的判据（双向：缺了红、多给也红）。
- **★★★ 规格常量与生成常量必须分开**（N-26）：同一常量同时决定「生成几条」与「断言应有几条」⇒ 同步改则等式永远成立。**问「这个差异是不是由被断言的东西自己供给的」。**
- **★★★ 判据自己漏了比没判据更危险**：正则/子串抽取会静默跳过整类样本 ⇒ 改 `ast` 按语法边界抽，先用已知命中样本验召回。
- **★★★ 不做「关键字判文本对错」的闸**（R77 ⑧）：抽 `\bsize\b` ⇒ 「**没有 size 这个键**」提到却在否定 ⇒ 两 arm 都红。**词是否出现不分肯定否定**，改判**产物里实际写了什么**。问句：换成正反问句，结论会翻吗？
- **★★★「A ⊆ B」要核两端**（T-L27c v2）：只遍历 A ⇒ A 被删一条时那条不再被遍历 ⇒ 断言空、全绿。先核 **A 自身完整性**再核成员关系。
- **★★★ 散文里的数字必须自带算式**（T-R2）：漂移全都「一直都在」，因为数字只被人读 ⇒ 每个数旁站一个**能被机器复算的算式**；能算的必须算。
- **★★★ 同名字段不保证同源** ⇒ 先问「这个字段来自哪一层」，再决定能不能加/顶替。
- **★★★ 两个判分器不一致 = 实现漏项，不是口径差异**：加题型/改卷前先问「目标判分器认识这种题吗」；守它 = 自比 A==A + 三向变异。
- **★★★ 加题压不下整体退化率，分层报才是价值**：两层**不可相加或比大小**；`_coverage` 写明覆盖哪层（另一层 `0/0` 不是 0 分）；分层按族取整。
- **★★★ k 遍表决要两级 + 全同短路**：一级只判「是否拒绝」严格过半，二级同票类定细分、平票取保守；`over_refuse` 必须归 `refuse`。
- **★★ 凡「等式」都要核两端**（`a/b` 与写着的 `p%`），只核左边 = 核了一半。**正则交替长选项排前面**（`jsonl` 在 `json` 前）；**「提及」≠「引用」**（按 basename 找引用 ⇒ token 必须含 `/`）。
- **★★ 指标选错比判据写错更隐蔽** ⇒ 每个门槛先问「它失败时责任算在谁头上」。**过滤写在收录之后 = 没有过滤**；同一组探针不能给两侧共用。
- **★★★ 「分数必须涨」是错的正向判据**（N-35，第五次复发）：它依赖**基线的偶然状态** —— 旧态已满分（无空间）或旧态失败另有原因，都会假红。**正解按题现取**：「旧态被该键压住的题」必须全转绿，与总数无关。问句：**这条判据在「工具已经完美」的输入上还成立吗？**
- **★★★ 「等价性」比「分数上升」硬**（N-35）：判分时跳过 ≡ 数据里把这些键物理删掉 ⇒ 逐题相同。不依赖分数高低、不依赖基线。问句：**能不能不问「变好了多少」，改问「和它应该等价的另一条路走得一样吗」？**
- **★★ 反向判据必须成对**（N-35 / S-63）：只测「该豁免的豁免了」⇒「全部豁免」也绿（放水也是过）；只测「该判的判了」⇒「一个都不豁免」也绿。**两条反向同时立才钉住「分开」。**

### B. 测量错误
- **★★★ 两侧字集不同时 `comm` 双向误判** ⇒ `git -c core.quotepath=false ls-files`。**`$?` 会被管道吃掉** ⇒ 重定向到文件再取 rc。
- **★★★ 闸做得越好，越看不出上游不同步** ⇒ 先问「闸替它吸收了什么」。**「主仓全绿」证明不了「新分支被跑过」**。
- **★★★ 不要把成功建立在 git 的惰性行为上**（`checkout-index -a -f` 后 928 个 LF 一个没变、rc=0）⇒ 自己写字节、自己验字节。
- **★★★ 空的东西最干净**（bundle 不带 `HEAD` ⇒ 四信号全「成功」而工作树 0 文件）⇒ 判据落在根因。
- **★★★ 行尾规范化会改掉产物里嵌的 sha** ⇒ 先规范化卷 → 再生成嵌 sha 的产物 → 最后 add；回查「产物里的 sha == 磁盘上的 sha」。
- **★★★ 单配置会把「缺陷」读成「运气」**：换第二个模型的价值不是排名，是让同一段文字有第二个执行者；弱稳定模型的单次数**必须带另一遍的值**。
- **★★ 验证产物本身会过期且无声** ⇒「完整」与「当前」是两个判据。**`SIGTERM` 杀父≠杀子**（残留抢 `.solve.lock`，满屏 `pipeline: False`）。**一律传绝对路径**（docstring 相对路径按 CWD 解析）；`--emit` 后必须 `--check` 同一路径。
- **★★★ 改判分口径 ⇒ 兄弟臂成绩单必须一起重出 + 出 bridge**（N-35）：负控的「逐字节复算」随即红，**那是正确的连带反应**。只重出被盯的那几份 ⇒ 同卷兄弟臂（`v2` 与 `v3s`）立刻不同源。旧代归档、新代重出、bridge 脚本现读。问句：**这份成绩单有没有「兄弟臂」？**
- **★ 跑「取帮助」前先确认脚本会不会把缺省参数当任务执行**：`score_baseline.py --help` 不认 `--help`，直接跑了一遍旧候选并写了 artifact。

### C. 证据与锚点
- **★★★ 加闸前先问「谁触发这个闸」，触发器自己有没有闸**（hook 不入库 ⇒ 新 clone 后静默消失）⇒ 判据不能放在被它守护的东西里。
- **★★★ 锚点闸守同一性，不守正确性**（N-34）：SYS 回滚到旧 sha ⇒ 更正跟着一起消失，而闸只锚「sha 变没变」。**回滚证得了「回到原样」，证不了「原样是对的」** ⇒ 「回滚/一致」类判据必须另配正向正确性判据。
- **★★★ 闸的名义 ≠ 闸的行为**（v4）：S-42 报错写「分母不等时禁止 Δ」，实现却**无条件禁**⇒实现比说明严。**改判据先读代码行为，别读报错文案**；文案由数据渲染，不许硬编码。**同一份 artifact 不得自己说两句话。**
- **★★★「门禁全绿」只证明工作区好，不证明提交好** ⇒ 对提交本身 clone 复验（`check_commit.py`）。
- **★★★ 同一类闸只装在一个调用点 = 没装** ⇒ 加/改评分器时先横向问「同类闸在另一个评分器上装了吗」。
- **★★★ 只证「没改坏」不证「改对了」** ⇒ 等价脚本挡不住「改动根本没生效」，必须另加正向判据。**前置闸用 `isdir` 挡不住「有但是空的」** ⇒ 校验内容量级。
