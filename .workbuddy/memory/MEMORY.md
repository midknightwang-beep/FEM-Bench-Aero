## 通用坑

### A. 判据设计（写判据的人最容易被判据骗）
- **★★★ 判据不能依赖顺序/位置/时间戳**（`max(mtime)`、`i % 3`）⇒ 问「**shuffle 一下数据集，这条还是这道题吗**」。
- **★★★「默认拒绝 + 手抄名单」必然漏** ⇒ **名单里的「具体值」比名单本身更危险**。修法：结构性规则 + 一条**不读名单**的判据（从源库现取、双向：缺了红、多给也红）。**判「某集合该有什么」时，若该集合由被判对象生成，这条判据等于没有。**
- **★★★ 判据自己漏了比没判据更危险**：`\b` 不成立只抓 5/19；T-B2RULES 重演——正则抽 `raise ValueError` 前缀时，占位符紧贴冒号那类（`must be > 0`）被整条跳过 ⇒ 删掉一条规则自检照样全绿。**改 `ast` 按函数边界抽**，并先拿已知命中样本验召回。
- **★★★ 规格常量与生成常量必须分开**（N-26 二次变体）：`CONTROL_TARGET` 同时决定「生成几条」与「断言应有几条」⇒ 同步改则等式**永远成立**。拆 `CONTROL_SPEC`。**问「这个差异是不是由被断言的东西自己供给的」**。
- **★★★ 文字与代码的一致性不能靠手写**（T-B2B5 v3 / R77 ⑧）：自然语言规则没有机器检查它与 `_validate` 说同一件事，人写错一次就把过拒率从 0% 推到 30%。修法：规则表 + 由表**渲染**文字、数字从探针取；闸 = 双向实测（越界必拒 **且** 合法必放）+ `ast` 反向覆盖 + 区块逐字节 diff。**不做「关键字判文本对错」的闸**（换个说法就绕过，还养成假安全感）。
- **★★★ 同名字段不保证同源**（§12 清理，自查拦住）：`grep -rho` 一把抓 `"split": …` 时把 `manifest.json` 等无关 json 一起聚了，得出 25+22+27 = **74**（而数据集只有 64 条）⇒ 差点写进里程碑行。**先问「这个字段来自哪一层」，再决定能不能加**；划分只认 `dataset_card.md`（v1.0 = 25/17/**13**，v1.1 扩到 **22**，两版本别混）。
- **★★★ 散文里的数字必须自带算式，否则没人读得出它错**（T-R2）：看板三处漂移**全都「一直都在」**（段 A「10 项里 8.5」而明细 **9** 行、8.5/10=85% vs 显示 88%，**横跨 8 个版本**；三口径全量 38% vs 合计 49%，漂 **5 版**；段 B 达标 8/8 vs 同格 87.5%）。**共同点：数字只被人读，而人只在写那一段时读它**。修法 = 每个数旁边站得下一个**能被机器复算的算式**（`roadmap_selfcheck.py` R1–R6 / S-62 / NC-76），**解析不到判红不 skip**，**无法复算的行必须显式标「无算式」并由闸单列点名**；且**能算了就必须算**（A+D 已从豁免改成权重归一的 92.1%）。
- **★★ 核了左边忘右边 = 核了一半**（T-R2 自检 T7）：`a/b = p%` 只复算 `a/b`、不核写着的 `p` ⇒ 把右边改错闸**全绿**。凡「等式」都要核两端。
- **★★ 正则交替顺序写反 = 假红**：`\.(?:json|jsonl)` 把 `x.jsonl` 截成 `x.json` ⇒ **长选项永远排前面**。
- **★★「提及」≠「引用」，也≠「点名」**：按 basename 找引用 ⇒ token 必须含 `/`；整行扫 `NC-\d+` 会把正文描述当清单点名 ⇒ 只从结构化清单段读。
- **★★ 指标选错比判据写错更隐蔽**：用「对照建对率」当「拒答题可否单独引用」的门槛 ⇒ 把建模能力的锅算到拒答头上（建对 65% 而 0 条被拒，警告照样触发）。**每个门槛先问「它失败时责任该算在谁头上」**。
- **★★ 过滤写在收录之后 = 没有过滤**（翼盒抽进了 `unknown structure family`）⇒ 先判整句归属再收片段。**同一组探针不能给两侧共用**（`inside` 带 `mutate` ⇒ 合法值也塞未知键、必然被拒 ⇒ 自相矛盾地红）。

### B. 测量错误（工具错了，结论越像真的）
- **★★★ 两侧字集不同时 `comm` 双向误判**（一小时内三次）⇒ `git -c core.quotepath=false ls-files`；**先问「两侧是不是同一套字符集」**。
- **★★★ `$?` 会被管道吃掉** ⇒ 被测命令后不能有任何命令，重定向到文件再取 rc。
- **★★★ 闸做得越好，越看不出上游不同步**（通过率 100% 掩盖 59/64 首轮错）⇒ **先问「闸替它吸收了什么」**。
- **★★★「主仓全绿」证明不了「新分支被跑过」**（`if problems and public_mode` 短路）⇒ 新分支必须在能走到它的环境里验；验不到就明写「本向未验证」。
- **★★★ 工具必须读规则表，不能另立一套**；**不要把成功建立在 git 的惰性行为上**（`checkout-index -a -f` 后 928 个 LF 一个没变、rc=0）⇒ 自己写字节、自己验字节。
- **★★★ 空的东西最干净**（bundle 不带 `HEAD` ⇒ verify/fsck/status/clone 四信号全「成功」而工作树 0 文件）⇒ **判据落在根因**。
- **★★ 验证产物本身会过期且无声** ⇒ **「完整」和「当前」是两个判据**，后者只能靠 `behind_by` 问；用「当前 HEAD」造旧包等于没造。
- **★★★ 单配置的测量会把「缺陷」读成「运气」**：同一句歧义规则，glm 0/20 过拒（没按字面核）、ds 6/6 全拒 ⇒ 只跑 glm 会得出「prompt 没问题」。**换第二个模型的价值不是排名，是让同一段文字有第二个执行者**。
- **★★★ 两模型稳定性可差一个量级**（T-B2B5 v3）：同 prompt 重跑，glm 59/60（零翻转）、ds 49/60（翻 11 条）⇒ **连「可不可单独引用」这个判定都会跨档**（过拒 25%↔10%）。弱稳定模型的单次数必须带另一遍的值。
- **★ `SIGTERM` 杀父进程 ≠ 杀子进程**：残留子进程抢 `.solve.lock`，表现为满屏 `pipeline: False`；后台任务还会被系统挂起 ⇒ 长任务「一批一个任务 + 阻塞取输出」。

### C. 证据与锚点
- **★★★ 加闸前先问「谁触发这个闸」，触发器自己有没有闸**（hook 不入库 ⇒ 新 clone 后静默消失）⇒ **判据不能放在被它守护的东西里**。
- **★★★「门禁全绿」只证明工作区好，不证明提交好**（12 个改动全漏而负控与 claims 都没发现）⇒ 对提交本身 clone 复验；`check_commit.py` G4 守它。
- **★★ sha256 只证「文件没被换」不证「数对」** ⇒ claim 计数要有闸比对 artifact；**建完闸先查自己刚写的东西有没有绕开它**。**无工具读的 = 无闸**（R58）。
- **★★ 前置闸用 `isdir` 挡不住「有但是空的」** ⇒ 校验**内容量级**；问「**这个闸有没有可能被空壳满足**」。

### D. 负控
- **★★ 负控五条**：①不只断言「是否红」，还要断言**「红的原因对不对」**；②变异锚点**现取不写死**；③锚点缺失判红不 skip；④新闸测「自比 A==B」；⑤消掉漂移面要配闸防它长回来。
- **★★★ 变异锚点写死的不是数字，是「基线长什么样」**（三次复发）⇒ 问「**这个差异是不是由基线状态供给的**」。
- **★★ 闸与负控可能互为前提**（S-45 读上一轮 JSON ⇒ 改名后首跑必红、重跑自愈）⇒ 新增负控**先改 INDEX 累计数**再跑。
- **★★ 放宽必须有边界（R69）**：①哪里仍必须为 0 ②例外带 reason ③例外不进对外数字。**能判的不变量优于需维护的名单**。
- **★★ 子串匹配的假通过是「静默偏高」**（R70）⇒ 纯 ASCII 加词边界，**中文别名仍按子串**；**同一通道双向**，也修假红 ⇒「这次只会更严」的直觉是错的。
- **★ 只留最新一份**（`negative_controls_<N>.json`），旧的 `git mv` 到 `reports/archive/`，INDEX 历史列表同步加编号。

### E. 文档与记忆
- **★★ 注入的 `working_memory_content` 是会话开始时的快照** ⇒ 改记忆/文档前先 Read 磁盘。
- **★★★ 分母里没有的那一项，往往正是最缺的那一项** ⇒ **求和之前先数被求和的清单有没有漏掉正在讨论的对象**。
- **★★ 文档会描述「不存在的功能」**（README 写 `--url` 而全文无 urllib；报告写「已移入 archive」而文件还在原地）⇒ **没人执行的能力写进文档就没人验**；发版后按文档逐条跑一遍。
- **★★ 一次改多处数字，改完必须全局 grep 旧值**（`74/74`、旧 prompt sha）：漏一处要等下一轮闸（S-04/S-05/S-27）才看得见。
