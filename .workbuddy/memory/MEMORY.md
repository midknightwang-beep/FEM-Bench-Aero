### A. 判据设计（写判据的人最容易被判据骗）
- **★★★ 判据选对象不能依赖顺序/位置/时间戳**：`latest_scorecard()` 用 `max(mtime)` ⇒ 重算一个锚点就把别的版本 mtime 写新、负控改咬（F-5）；clone 后 mtime 全同 ⇒ 退化成 `listdir` 顺序 ⇒ **换机不可复现**。同族「位置耦合」：`stats['L1']`、`i % 3`、`cands[:n]`。判断法：**shuffle 一下数据集，这条还是这道题吗**。
- **★★★「默认拒绝 + 手抄名单」必然漏，且漏了没闸会报**（T-F7）：`ROOT_KEEP` 写了 `.gitignore`、漏了同作用的 `.gitattributes`；P6（快照 vs manifest）看不出来，因为 manifest 正是同一个 `classify()` 产的（**自证循环**）。修法：①规则结构化 ②加一条**不读名单**的判据（从源库现取、双向：缺了红、多给也红）。**判「某集合该有什么」时，若该集合由被判对象生成，这条判据等于没有。**
  **★ 第二次复发（T-D6 §7c，F-10）**：bundle 闸 C9 的 `doc_only` 也是手抄名单，且**写死了 `2026-10-31.md`**（为了躲自指把日期拆成字符串拼——**防住了自指，没防住日期**）⇒ 第二天必红；`check_claims.json` 从来不在名单 ⇒ **每轮收口都假红一次**，人会养成「又是那个红」的习惯，等于放宽失效。改成「目录 + 扩展名」结构性规则，并用 8 例正反例钉住（含任意日期日志为真、`reports/` 下 `.sh` 为假）。**⇒ 名单里的「具体值」（日期/文件名）比名单本身更危险。**
- **★★★ 判据红了，先怀疑脚手架**（T-F7）：自检首版 8/12，三个 BAD 全是 `open(...,'w')` 在 Windows 把 `\n` 写成 CRLF 致 sha 假红。**构造测试自己写字节，用 `newline=''`。**
- **★★★ 判据自身含被检测词 ⇒ 自指误报**（T-D4）：用 `_m('密','级')` 拆开拼接，文件文本不含完整串、运行时等价。**别用「豁免判据自身」**（allowlist 腐化起点）。
- **★★ 判据自己漏了比没判据更危险**：`\b` 在 `_d30` 处不成立 ⇒ 只抓 5/19 条还给个好看的假数。**写完先拿已知命中样本验召回**。
- **★★ 正则交替顺序写反 = 假红**：`\.(?:json|jsonl)` 把 `x.jsonl` 截成 `x.json`。**长选项永远排前面**。字符类要覆盖输入的实际字符集（`PATH_RE` 不含 `{}` ⇒ 占位符被截成 `/x.txt`）。
- **★★「提及」≠「引用」**：按 basename 找引用时，正文描述规则适用范围会写裸文件名。**token 必须含 `/` 才算引用**。
- **★★ P1 类判据不能用分类函数重判**：闭包拉回的文件在分类规则里仍属 drop 类。要「判 False **且**不在 `pulled_by_reference` 里」。
- **★★ 只比 sha256 证「文件没被换」，不证「规则生效」**（T-F7）：`.gitattributes` 一字不差放进快照也可能不生效。要**问工具本身**（`git check-attr`），不自己解析规则文件（第二套实现）。

- **★ 冻结要冻结「整行」不是「参数」**：`case_id→style_idx` 防不了措辞改动（R65/S-52）。

### B. 测量错误（工具错了，结论越像真的）
- **★★★ 两侧字集不同时 `comm` 双向误判**（T-F2，一小时内犯三次）：`git ls-files` 默认 `quotepath=true` 把中文转义，`find` 是真 UTF-8 ⇒ 三次都「发现」了假差异。修法 `git -c core.quotepath=false ls-files`。**比对前先问「两侧是不是同一套字符集」**。
- **★★★ `$?` 会被管道吃掉**：`cmd | tail; echo $?` 拿的是 `tail` 的退出码（永远 0），据此断言过假缺陷。⇒ **被测命令后不能有任何命令**，一律重定向到文件再取 rc。`grep | head` 同族（制造假「没红」）。
- **★★★ 恒真式外观与正常闭合一样**（N-26；T-B1KPI 再犯一次）：都印 `ok=True`、都印 `A = B + C`；`_denom_audit` 的 pool 取自已剔除的行 ⇒ 那条「不闭合」从未生效。**第二次的写法更隐蔽**：`sum(Counter值) == len(items)` —— 按定义恒成立，任何未知类别都能「闭合」⇒ 那一向自检永远绿。改成「类别必须落在已知集合」才真会红。⇒ **问「这个等式有没有可能不成立」**；一处真一处假可写在同一段代码里。
- **★★★ 闸做得越好，越看不出上游不同步**（T-B1KPI）：修复循环把首轮错误全部吸收（`turns_histogram={1:5,2:57,3:2}`、`n_unresolved=0` 读起来「几乎没失败」），实际 59/64 条首轮都错，且集中在**两处我方缺陷**（required 键 prompt 没写、prompt 教了一个 schema 拒收的键）。**「通过率 100%」要先问「闸替它吸收了什​么」**。同族于「门禁全绿只证明工作区好」。
- **★★★「主仓全绿」证明不了「新分支被跑过」**（T-F3）：`if problems and public_mode` 在 problems 空时短路 ⇒ 另一环境才 `NameError`。**新增分支必须在能走到它的环境里验**；验不到就明写「本向未验证」。
- **★★★ 工具必须读「规则表」，不能另立一套**（T-D3）：规范化器一刀切转 CRLF 把 2 个 `*.sh` 也转了，与同批写的 `.gitattributes` 自相矛盾。正确做法 `git check-attr` 逐文件问。**规则只有一处，第二处实现就是 bug。**
- **★★★ 不要把「成功」建立在 git 的惰性行为上**（T-D3）：加 `eol=crlf` 后跑 `checkout-index -a -f`，928 个 LF 文件一个没变（rc=0 无报错）。⇒ **自己写字节、自己验字节**；命令跑通 ≠ 效果发生。
- **★★★ 空的东西最干净**（T-D6）：`bundle create x --branches --tags` **不写 `HEAD`** ⇒ verify/fsck/status/clone 四个信号全「成功」而工作树 0 文件。⇒ **判据落在根因（包内有没有 HEAD），不能落在后果（clone 后空不空）** —— 后果取决于引用构成（1 分支 git 会自选、6 tag 选不出来）。
- **★★ 验证产物本身会过期且无声**（T-D6）：bundle 不随提交更新，落后 25 提交而 verify 一直绿。**「完整」和「当前」是两个判据**，后者只能靠 `behind_by` 问，且还要问「落后的是否只有文档」。
- **★★ 用「当前 HEAD」造旧包等于没造**（T-D6/NC-56d）：`main` 仍指最新 ⇒ `behind_by` 恒 0、变异向退化成空操作。必须在**提交之间**逐次打包。
- **★★ 夹具不真会让判据假红**（T-D6）：临时库没写 `.gitattributes` ⇒ 行尾由 clone 端 `core.autocrlf` 决定。**判据没错，是夹具不真**。
- **★★ 自检「全绿」可能是假绿**：8 向全过但每行都带 `[not_applicable]`（忘了调 `_mk_repo()`）。**自检必须打印明细** —— 判据没跑起来与判据通过外观一样。
- **★★ 汇总/明细/「跑完了」都会骗人**：`batch_summary` 漏写、键名不符（`case` vs `case_id`）、长期「没跑完」掩盖「跑通了会红」。**先打印「命中数/总数」，命中 0 必须报错**。
- **★★ 放宽最容易的错法是顺手把判定条件也改宽**（T-F3/R75）：正确写法是给每条豁免配**谓词**（问「失败原因是否恰好是这个造成的」）；按 id 直接豁免 = 废掉判据。验法：① 加参数前后**逐字节比对输出**；② 构造「该红的仍红」三向。
- **★ 口径参数漏传 ⇒ 假 FAIL**（漏 `--spec` 印 residual 99.99%）⇒ **先怀疑参数再怀疑模型**。

- **★ 改别人结论前先回原文**；**记「新发现」前先 grep 旧脚本**（N-28 旧脚本第 13 行早有原文）。旧账未清 ≠ 新发现。

### D. 负控
- **★★ 负控五条**：①不只断言「是否红」，还要断言**「红的原因对不对」**（强判据吃弱判据 ⇒ 弱判据永假绿）；②变异锚点**现取不写死**；③锚点缺失判红不 skip；④新闸测「自比 A==B」；⑤消掉漂移面要配闸防它长回来。
- **★★★ 变异锚点写死的不是数字，是「基线长什么样」**（NC-56d 第三次复发）：那向靠「另一侧原本为 None」，artifact 一升级两侧都是整数就退化成空操作。⇒ 问「**这个差异是不是由基线状态供给的**」。

- **★★ 放宽必须有边界（R69）**：写明 ①哪里仍必须为 0 ②例外必须带 reason ③例外不得进对外数字。**能判的不变量优于需维护的名单**。
- **★★ 子串匹配的假通过是「静默偏高」**（N-28/R70）：`a in text` 在「键名是另一键前缀」时判对。修法只约束纯 ASCII 标识符 `(?<![A-Za-z0-9_])X(?![A-Za-z0-9_])`，**中文别名仍按子串**（中文没词边界，加边界=改坏判据）。**同一通道双向**：也修假红 ⇒「这次只会更严」的直觉是错的。
