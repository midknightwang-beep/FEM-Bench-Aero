## 通用坑

### A. 判据设计（写判据的人最容易被判据骗）
- **★★★ 判据不能依赖顺序/位置/时间戳**（F-5 `max(mtime)`；`stats['L1']`；`i % 3`）⇒ 问「**shuffle 一下数据集，这条还是这道题吗**」。修法：锚结构化字段（CLAIMS C-032 artifact 列）+ NC-70 守。
- **★★★「默认拒绝 + 手抄名单」必然漏，且漏了没闸会报**（T-F7 漏 `.gitattributes`；T-D6 名单里写死日期）⇒ **名单里的「具体值」比名单本身更危险**。修法：结构性规则（目录+扩展名）+ 一条**不读名单**的判据（从源库现取、双向：缺了红、多给也红）+ 正反例钉住。**判「某集合该有什么」时，若该集合由被判对象生成，这条判据等于没有。**
- **★★★ 判据红了先怀疑脚手架**（T-F7 三个 BAD 全是 Windows 文本模式把 `\n` 写成 CRLF 致 sha 假红）⇒ 构造测试自己写字节，用 `newline=''`。
- **★★★ 判据自身含被检测词 ⇒ 自指误报**（T-D4 用 `_m('密','级')` 拆开拼）；**别用「豁免判据自身」**（allowlist 腐化起点）。
- **★★ 判据自己漏了比没判据更危险**（`\b` 在 `_d30` 不成立 ⇒ 只抓 5/19 还给个好看的假数）⇒ 写完先拿已知命中样本验召回。
- **★★ 正则交替顺序写反 = 假红**：`\.(?:json|jsonl)` 把 `x.jsonl` 截成 `x.json` ⇒ **长选项永远排前面**；字符类要覆盖输入的实际字符集。
- **★★「提及」≠「引用」**：按 basename 找引用 ⇒ **token 必须含 `/`** 才算引用。
- **★★「提及」≠「点名」（N-33 复发）**：整行扫 `NC-\d+` 把正文逐条描述当成清单点名 ⇒ 覆盖恒成立。只从结构化清单段读（`C-0xx：` 之后、第一个 `（` 之前）。
- **★★ P1 类判据不能用分类函数重判**：闭包拉回的文件在分类规则里仍属 drop ⇒ 要「判 False **且**不在 `pulled_by_reference` 里」。
- **★★ 只比 sha256 证「文件没被换」不证「规则生效」**（T-F7）⇒ 问工具本身（`git check-attr`），不自己解析规则文件（第二套实现）。
- **★★ 用关键字判层级/性质会被一句无害措辞翻掉**（T-A14 `is_diag`）⇒ **判据用到的词是保留字**；根治是改结构化字段，不是维护黑名单。
- **★ 冻结要冻结整行不是参数**（R65/S-52）；**判据在子集上失效 ⇒ 隔离+双报，不改题**（R66）；**计数好看不是闸**。

### B. 测量错误（工具错了，结论越像真的）
- **★★★ 两侧字集不同时 `comm` 双向误判**（T-F2，一小时内三次）⇒ `git -c core.quotepath=false ls-files`；**先问「两侧是不是同一套字符集」**。
- **★★★ `$?` 会被管道吃掉**（`cmd | tail; echo $?` 拿的是 `tail` 的 0）⇒ **被测命令后不能有任何命令**，一律重定向到文件再取 rc。
- **★★★ 恒真式外观与正常闭合一样**（N-26，两次）⇒ 问「**这个等式有没有可能不成立**」；`sum(Counter值)==len(items)` 按定义恒真、未知类别也能「闭合」⇒ 改成「类别必须落在已知集合」才会红。
- **★★★ 闸做得越好，越看不出上游不同步**（T-B1KPI：通过率 100% 掩盖 59/64 首轮错）⇒ **「通过率 100%」先问「闸替它吸收了什​​么」**。
- **★★★「主仓全绿」证明不了「新分支被跑过」**（T-F3 `if problems and public_mode` 短路 ⇒ 另一环境才 `NameError`）⇒ 新分支必须在能走到它的环境里验；验不到就明写「本向未验证」。
- **★★★ 工具必须读规则表，不能另立一套**（T-D3 规范化器一刀切把 2 个 `*.sh` 也转了）⇒ **规则只有一处，第二处实现就是 bug**。
- **★★★ 不要把成功建立在 git 的惰性行为上**（T-D3 `checkout-index -a -f` 后 928 个 LF 一个没变、rc=0 无报错）⇒ **自己写字节、自己验字节**；命令跑通 ≠ 效果发生。
- **★★★ 空的东西最干净**（T-D6 `bundle create x --branches --tags` 不写 `HEAD` ⇒ verify/fsck/status/clone 四个信号全「成功」而工作树 0 文件）⇒ **判据落在根因（包内有没有 HEAD），不能落在后果**（后果取决于引用构成）。
- **★★ 验证产物本身会过期且无声**（bundle 落后 25 提交而 verify 一直绿）⇒ **「完整」和「当前」是两个判据**，后者只能靠 `behind_by` 问。
- **★★ 用「当前 HEAD」造旧包等于没造**（NC-56d）⇒ 必须在**提交之间**逐次打包。
- **★★ 夹具不真会让判据假红**（临时库没写 `.gitattributes`，行尾由 clone 端 `autocrlf` 决定）。
- **★★ 自检「全绿」可能是假绿**（8 向全过但每行带 `[not_applicable]`）⇒ **自检必须打印明细**，判据没跑起来与判据通过外观一样。**★ 只跑自检绿 = 自证**：还要改坏实现，看自检会不会红（F-9 三向变异：谓词恒 True / 恒 False / 删掉一条判断，各须让某一向退化）。
- **★★ 「自指」不总是缺陷，要先问它在表达什么**（F-9）：`public_manifest.json` 既进公开集又记录 `source_head` ⇒ **记录它的那个提交必然让产物落后 1**。这不是 bug，是「产地必须随产物走」的代价；处理法是**把它做成黄（allow，附 why）不是红**，而不是把记录排除掉（那读的人就永远看不到产地）。
- **★★ 汇总/明细/「跑完了」都会骗人**（`batch_summary` 漏写、键名不符）⇒ **先打印「命中数/总数」，命中 0 必须报错**。
- **★★ 放宽最容易的错法是顺手把判定条件也改宽**（R75）⇒ 每条豁免配**谓词**（问「失败原因是否恰好是这个造成的」）+ 加参数前后**逐字节比对输出** + 「该红的仍红」三向。
- **★ 口径参数漏传 ⇒ 假 FAIL**（漏 `--spec` 印 residual 99.99%）⇒ **先怀疑参数再怀疑模型**；真错误用退出码说，`return 2` 当场验一次 rc。
- **★ 改别人结论前先回原文**；记「新发现」前先 grep 旧脚本。**动手改之前先证明被修的东西真的坏了。**
- **★ `SIGTERM` 杀父进程 ≠ 杀子进程**：前台长任务被杀后子进程残留抢 `.solve.lock`，表现为满屏 `pipeline: False` / `class=env` / `MSR 0/4`（同样的题单单独跑是 `[ok]`）。⇒ R61 要防「以为杀掉了其实没杀掉」。**后台任务还会被系统挂起**（三批 3.5 h 只推进 1 条）⇒ 长任务「一批一个任务 + 阻塞取输出」。
