## 通用坑

### A. 判据设计（写判据的人最容易被判据骗）
- **★★★ 时间耦合会伪装成确定性**（T-D3/F-5）：`latest_scorecard()` 用 `max(mtime)` 选被测对象 ⇒ 我重算一个锚点就把 v4 的 mtime 写新了，负控立刻改咬 v4、`NC-33`/`NC-36` 无端转红（**被测字段一个字节都没改**）。更狠的是 **clone 后所有文件 mtime 相同 ⇒ `max()` 退化成 `listdir` 顺序 ⇒ 换机跑结果不可复现**。**同族于「位置耦合」**：判据选对象时别依赖顺序、位置、时间戳，要么用内容锚（sha/版本号），要么用显式清单。
- **★★★ 位置耦合会伪装成确定性**：`stats['L1']`（全局累计）、`i % 3`（族内序号）、`cands[:n]` 都「看起来确定、实际依赖位置」。判断法：**shuffle 一下数据集，这条还是这道题吗**。
- **★★ 冻结要冻结「整行」不是「参数」**：`case_id→style_idx` 只防序号漂移、防不了措辞改动（R65/S-52）。
- **★★ 判据自己漏了比没判据更危险**：`\b` 在 `_d30` 处不成立 ⇒ 只抓 5/19 条还给了个好看的假数。**写完判据先拿已知命中样本验召回**。
- **★★ 正则交替顺序写反 = 假红**（T-D4）：`\.(?:json|jsonl)` 把 `x.jsonl` 截成 `x.json` ⇒ 报了 9 个假「artifact 缺失」。**长选项永远排前面**。
- **★★★ 判据文件自身包含被检测词 ⇒ 自指误报**（T-D4）：脚本/契约里直接写出检测词（受限标识类词、本机用户目录前缀）会把自己判红。解法 `_m('密','级')` 拆开拼接 —— 文件文本不含完整串、运行时字符串等价、检测力不变。**别用「豁免判据自身」的办法**（那是 allowlist 腐化的起点）。
- **★★「提及」≠「引用」**（T-D4）：按 basename 找引用时，正文里**描述规则适用范围**会写裸文件名（`AGENTS.md`/`CLAUDE.md`），那不是引用。规则：**token 必须含 `/` 才算引用**。
- **★★ P1 类判据不能用分类函数重判**（T-D4）：闭包拉回的文件在分类规则里仍属 drop 类，重新 `classify` 会把它们误报「残留」。要「判 False **且**不在 `pulled_by_reference` 里」。
- **★★★「默认拒绝 + 手抄名单」必然漏，而且漏了没有任何闸会报**（T-F7）：`ROOT_KEEP` 手写了 `.gitignore`、漏了作用完全相同的 `.gitattributes`；比「快照 vs manifest」的 P6 **看不出来**，因为 manifest 正是同一个 `classify()` 产出的（**自证循环**）。修法是①规则结构化（「根目录 `.git*` 配置文件一律 KEEP」）②加一条**不读名单**的判据（从源库现取、双向：缺了红、多给也红）。**判「某个集合该有什么」时，若这个集合本身由被判对象生成，那这条判据等于没有。**
- **★★「只比 sha256」证「文件没被换」，不证「规则生效」**（T-F7）：`.gitattributes` 一字不差地放进快照，也仍然可能因为位置/上下文而实际不生效。要**问工具本身**（`git check-attr` 问快照库、拿源库的回答比），而不是自己解析规则文件（第二套实现）。同族于 C 段「sha256 只证文件没被换不证数对」。
- **★★★ 判据红了，先怀疑脚手架**（T-F7）：自检首版 8/12，三个 BAD 全是 `open(...,'w')` 在 Windows 上把 `\n` 写成 CRLF 所致（sha256 假红）—— 与 T-D3「以为 `json.dump` 写 LF、去加 `newline='\r\n'`」是同一个坑的镜像。**构造测试时自己写字节，用 `newline=''`。**
- **★ 计数好看不是闸**（T-F7）：`KEEP:根目录仓库配置 = 2` 掉了回去，没有任何东西会报；真正守住它的是 P8。别把「分类计数对」当成验证。
- **★★ 判据在子集上失效 ⇒ 隔离+双报，不改题**（R66/S-53）。**先证「失效」是真的** —— 不盲从自己上一版写的结论。
- **★★ 用关键字判「层级/性质」的闸，会被正文一句无害措辞翻掉**（T-A14）：`is_diag` 靠含「诊断」判层级，正文写「手写诊断报告」就把它判成 diag ⇒ 与共用 artifact 的 claim 冲突。**判据用到的词是保留字**；根治是改结构化字段，不是维护「哪些词不能写」黑名单。

### B. 测量错误（工具错了，结论越像真的）
- **★★★ 两侧字集不同时，`comm` 会把同一文件同时算进「只有左边」和「只有右边」**（T-F2，一小时内犯三次）：`git ls-files` 默认 `core.quotepath=true` 把中文名转义成 `\346\265\201...`，而 `find` 输出真实 UTF-8 ⇒ 三次都「发现」了不存在的差异（快照残留文件、缺 2 个文件），真值只有 1 个。**同族于「口径参数漏传 ⇒ 假 FAIL」**：比对前先问「两侧的字是不是同一套字符集」，先怀疑量具再怀疑对象。修法：`git -c core.quotepath=false ls-files`。
- **★★★ `$?` 会被管道和中间命令吃掉**：`cmd | tail -3; echo $?` 拿到的是 `tail` 的退出码（永远 0）。据此断言「`return 2` 没传到退出码」是**假缺陷**（实测 rc=2）。复发两次（分节 `echo` 夹在中间）。⇒ **被测命令后不能有任何命令**；一律「重定向到文件再取 rc」。
- **★★ `grep | head -3` 制造假「没红」**：验证「移走 hook 会红」时目标行被 `head` 截掉，差点记成没红。同族于上条。
- **★★ 自检「全绿」可能是假绿**：8 向全过但每行都带 `[not_applicable]` —— 定义了 `_mk_repo()` 忘在 `probe()` 里调用。**回 pass/fail 那一列看不出来** ⇒ **自检必须打印明细**（判据没跑起来与判据通过，外观一样）。
- **★★ 汇总/明细/「跑完了」都会骗人**：`batch_summary` 漏写、明细**键名不符**（`case` vs `case_id`）、长期「没跑完」的检查同时掩盖「跑通了会红」。**先打印「命中数/总数」，命中 0 必须报错**。
- **★★★ 恒真式在外观上与正常闭合一模一样**（N-26）：都印 `ok=True`、都印一行 `A = B + C`。`_denom_audit` 的 pool 取自已剔除的行 ⇒ 那条「不闭合」**从未生效过**。⇒ **判闭合问「这个等式有没有可能不成立」**；**一处真一处假可以写在同一段代码里**。
- **★ 口径参数漏传⇒假 FAIL**（漏 `--spec` 印 `residual 99.99%`）⇒ **先怀疑参数再怀疑模型**。
- **★ 真错误要用退出码说**：`return 2` 要**当场 `echo $?`** 验一次。
- **★ 改别人的结论之前，先回去读原文**：曾误以为别人把方向写反，读原文确认是我记串了。
- **★★ 记「新发现」前先 grep 旧脚本**：N-28 我记成新发现，旧脚本第 13 行早有原文。**旧账未清 ≠ 新发现**。
- **★★★「主仓全绿」证明不了「新分支被跑过」**（T-F3）：给判据加开关时，主仓全绿可能只是因为**那段代码被 `and` 短路跳过了**（`if problems and public_mode` 在 `problems` 为空时从不求值 `public_mode`）⇒ 到另一环境才 `NameError`。**新增分支必须在「能走到它」的环境里验**；验不到就明写「本向未验证」，别假装验过。
- **★★ 放宽最容易的错法是顺手把判定条件也改宽**（T-F3/R75）：加 `--public` 这类开关，正确写法是给每条豁免配**谓词**（问「失败原因是不是恰好这个原因造成的」），**按 id 直接豁免 = 把判据废掉**——而它写起来最省事。验法：① 加参数前后**逐字节比对输出**（连一个空格都算差异）；② 构造「该红的仍红」三向。
- **★★★ 工具必须读「规则表」，不能另立一套**（T-D3）：行尾规范化器一刀切转 CRLF，把 2 个 `*.sh` 也转了，而**同一批**写的 `.gitattributes` 声明 `*.sh eol=lf` ⇒ 工具与规则自相矛盾，凭空造出「本地改了、clone 没改」的新漂移面。正确做法是 `git check-attr` 逐文件问规则。**同族于「判据自己漏了」：规则只有一处，第二处实现就是 bug。**
- **★★★ 不要把「格式化成功」建立在 git 的惰性行为上**（T-D3）：加了 `* text=auto eol=crlf` 后跑 `git checkout-index -a -f`，**928 个 LF 文件一个都没变**（rc=0、无报错）。⇒ **自己写字节、自己验字节**；「命令跑通了」≠「效果发生了」。
- **★★ Windows 上 Python 文本模式默认就写 CRLF**（`os.linesep`）：误以为 `json.dump` 写 LF，给两道闸加 `newline='\r\n'`，直到规范化器报「已处理 0 个」才发现**自己在修一个不存在的问题**，已回滚。⇒ **动手改之前，先证明被修的东西真的坏了**（同源「先回原文」）。

### C. 证据与锚点
- **★★★ 加闸之前先问「谁触发这个闸」，触发器自己有没有闸**（T-D5b/R74）：hook 不入库 ⇒ 新 clone 后闸**静默消失**且无人报错（R58 落在触发器上的形态）。**判据不能放在被它守护的东西里**（同语反复），要放在不依赖该触发机制的入口。
- **★★ sha256 只证「文件没被换」不证「数对」**（R62）：claim 计数必须有闸比对 artifact；**建完闸先查自己刚写的东西有没有绕开它**。无工具读的 = 无闸（R58）。
- **★★ sha256 锚点会被行尾悄悄废掉**（T-B1）：`autocrlf=true` + 无 `.gitattributes` ⇒ 工作区 LF/CRLF 混合 ⇒ clone 后 **61.6% 文件 sha 变**。**「本机跑绿」证明不了「换机能跑绿」**。判别法：`git ls-files --eol`。
- **★★ 行尾两端各有一批锚点，不存在单一配置全绿**：默认 clone 卷 sha = 权威值、S-57 绿；关 autocrlf 则另一套绿、原锚点红。⇒ 加 `.gitattributes` 是**一次性全链重新封存**，须单独立项。
- **★★★「门禁全绿」只证明工作区好，不证明提交好**：`08dc696` 只 add 了新增文件、12 个改动全漏（含真正实现修复的 `evaluate.py`），**负控与 claims 全绿都没发现**（它们跑工作区）。⇒ **要对提交本身做 clone 复验**；已建 `check_commit.py`（G4 = 暂存区 == 工作区全部非白名单改动）。
- **★ 按当前卷重跑带版本号的诊断脚本 = 静默改历史证据**：诊断脚本必须有 `--label`/`--tasks`，历史产物**只许回滚不许覆盖**。
- **★★ 前置闸用 `isdir` 只挡「完全没有」，挡不住「有但是空的」**：`mkdir modeling` 就能骗过，静默产出 `exam 3/25 (12.0%)` 假成绩。⇒ 闸要校验**内容量级**，并问「**这个闸有没有可能被一个空壳满足**」。

### D. 负控
- **★★ 负控五条**：①不只断言「是否红」，还要断言**「红的原因对不对」**（强判据吃弱判据⇒弱判据永假绿）；②变异锚点**现取不写死**（复发两次）；③锚点缺失判红不 skip；④新闸测「自比 A==B」；⑤消掉漂移面要配闸防它长回来。
- **★★★ 变异锚点写死的不是数字，是「基线长什么样」**（NC-56 d 第三次复发）：那向变异靠的是「另一侧原本为 None」；artifact 一升级两侧都是整数，这向就**退化成空操作**。⇒ 做变异时问「**这个差异是不是由基线状态供给的**」。
- **★★ 闸与负控可能互为前提（循环依赖）**：S-44(b) 要求 INDEX 负控行分母 == artifact 实读条数，而 NC-49 靠这条绿 ⇒ 新增负控后**先把 INDEX 累计数改到新分母**再跑。同类：S-45 读**上一轮** `check_claims.json` 记录的路径 ⇒ 改名/搬家后首跑必红、重跑自愈。**「首跑红、重跑绿」不一定是漂移，也可能是比较对象滞后一轮**。
- **★★ 放宽必须有边界（R69）**：任何「允许例外」的闸必须写明 ① 哪里仍必须为 0 ② 例外必须带 reason ③ 例外不得进入对外数字。**能判的不变量优于需要维护的名单**。
- **★★ 子串匹配的假通过是「静默偏高」**（N-28/R70）：`a in text` 在「键名是另一个键的前缀」时判对，**不留「本该过没过」的痕迹**。修法只约束纯 ASCII 标识符 `(?<![A-Za-z0-9_])X(?![A-Za-z0-9_])`，**中文别名仍按子串**（中文没词边界，加边界=把判据改坏）。**同一条通道双向**：也修假红 ⇒ **「这次改动只会更严」这个直觉是错的**。改判据必须先有构造性零差异（三路并行，只比两路在改前是自比、不算证据）。
