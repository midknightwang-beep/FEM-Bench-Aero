## T-B2B5 v4：拒答口径换代 k=3 多数表决（负控 77/77，产物重建）

线名：FEM-Bench-Aero ／ 关键实体：T-B2B5 v4、C-042、judge_refuse_majority、NC-77、ROADMAP v3.9 ／ 日期 2026-11-03

### 1. 为什么动（老王拍板「k=3 作主口径」）
v3 据 ds 单遍**过拒 5/20 = 25%** 判「不得单独引用」。但同 prompt 重跑是 **82.5 / 85.0 / 85.0%**、
过拒 **25 / 10 / 5%** ⇒ **连「可不可引用」这个判定本身都跨档**。花钱跑第 3 遍之前先做零成本诊断：
两遍交叉表显示 5 条过拒里 4 条是 `over_refuse → build_correct` **单向**（抖动），只有 1 条两遍都拒。

### 2. 做法（`judge_refuse_majority.py`）
- **两级表决**：一级只判「是否拒绝」是否**严格过半**（`cnt*2 > n`）；二级在同票类里定细分，平票取 `CONSERVATIVE`。
  直接对 verdict 取众数会 1/1/1 无解。
- **三票全同短路**：否则一致地没有输出（`ctl_no_output×3`）被二元化成 `invalid×3` ⇒ `undecided`，
  把「一致的失败」误当「判不了」。**这条同时保证自比 A==A**（三遍 == 一遍）。
- `over_refuse` 归 `refuse` 类；`counted` 只从 `VERDICT_TABLE` 取；判据**只 import `judge_refuse`**、聚合走 `J.agg()`。
- `_b2b5_majority_artifact.py` → `refuse_scores_v4_majority.json`（问题 0 条）。
