## 四、T-A12b（提交 `4b332bb`）：R32 口径 + 审计闭合 + 文本

### ★★★ N-26：`exam_full` 的分母闭合是**代数恒真式**（专家判成「展示问题」，实际是真 bug）

```
msr_l3.py:481   _FAUDIT = _denom_audit(exam_full_ids)
                exam_full_ids = exam_ids + v11_ids  ← 都取自 den_rows（已剔除 clarify/unresolved）
⇒ pool 全是 denominator=True 的行 ⇒ n_tasks_total ≡ n_counted、clarify/unresolved 恒 0
⇒ closure_ok 恒 True，而它正被写进 :483 的 `if not (...)`: [FATAL] 分母不闭合（R52）
⇒ 这条 FATAL 对 exam_full 这一路**从未生效过**
```

改前实测：glm `30 ≡ 30`、ds `29 ≡ 29`。真值 glm `34 = 30+4+0`、ds `34 = 29+4+1`。
同一函数另一处 `_EAUDIT` 传全量 `rows` ⇒ legacy 那份是真闭合 —— **一处真、一处假，写在同一段代码里**。

修法：新增 `exam_full_all_ids`（按 `_is_exam or _is_v11` 扫全量 `rows`）传给 `_denom_audit`；`counted` 集**不动**（MSR 分子仍用 counted）。
修后实读：glm/ds 均 `n_tasks_total=34`、`closure_ok=True`、`closure="34 = counted N + clarify 4 + unresolved 0|1 + …"`，与顶层 `exam_denominator_closure.exam_full` 同口径。

**为何无闸发现**：NC-58 测的是 `exam_full_closure.ok`（`msr_l3:516`，真算术 `exam_ids+v11_ids+dev_ids == len(den_rows)`），**两条路径互不覆盖**。

**★★ 教训（比这条 bug 更重要）**：**恒真式在外观上与正常闭合一模一样** —— 都印 `ok=True`、都印一行 `A = B + C + …`，只有把式子代进去看才发现左右恒等。
⇒ **判闭合必须问「这个等式有没有可能不成立」，而不是「它是不是 True」。**
